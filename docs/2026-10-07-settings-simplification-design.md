# 设置页简化设计

日期：2026-10-07

状态：2026-10-07 已完成代码重构及静态检查；按 AGENTS.md 未启动应用进行运行验收。存储、插件安全边界及用户数据规则保持不变。

## 1. 重构前的复杂度

重构前设置页 JavaScript 约 2400 行，AHK 设置宿主约 1200 行，此外还有窗口选择和按键录制模块。部分代码承担必要的专用交互，主要可减少的部分是：

- 普通字段、工具、应用快捷键及窗口分别维护差异、dirty 标志和冲突规则。
- 页面与宿主重复处理基线、规范化和状态，保存请求包含多个域标志。
- 多个全局回调及独立请求状态增加了过期消息处理的分支。
- 普通设置使用手写 HTML，工具设置又有按工具身份分支的控件生成逻辑。
- 新工具在保存前已有宿主准备流程、暂存身份与异步回执，但没有任何功能需要在保存前执行它。

目标是减少状态和执行路径，同时保留输入校验、原子保存、异步结果匹配及密码保护。

## 2. 统一模型

页面编辑器只维护：

```text
schema：宿主提供的字段和展示定义
base：进入编辑时的公开配置快照
draft：当前公开配置草稿
status：loading / editing / saving / error
```

`sessionId`、`revision` 和 `requestId` 是消息及并发控制信息，不再为每个配置域维护独立版本、stamp 或保存回执缓存。异步请求通过同一个请求封装匹配结果；保存一次只允许一个活动请求。

公开配置只包含可编辑字段，不包含使用统计、查询缓存、窗口运行状态或数据库诊断。展示数据与草稿分开。dirty 使用一个统一比较函数，比较规范化后的可编辑数据；不同时维护字段集合和各域 dirty 标志。

密钥使用明确的编辑意图：`keep`、`set`、`clear`。基线只包含是否已设置；真实凭据留在宿主，查看/复制使用独立辅助请求。默认配置与用户覆盖继续保存在主库，不向运行中的编辑器提供代码默认值兜底。

## 3. 保存与取消

```text
读取主库 → 创建 base / draft → 编辑 draft
                           ↓
             保存完整的可编辑 draft
                           ↓
           宿主规范化、校验并计算与 base 的差异
                           ↓
         单次事务检查 revision，写入发生变化的域
                           ↓
          提交、应用运行配置、返回最终公开快照
```

- 页面负责即时填写提示，宿主负责最终完整校验；两者使用同一份字段规则。
- 不修改原有已保存状态来准备候选。所有数据库变更通过既有仓储，放在同一个 AppStore 事务中。
- 成功时用最终快照替换 base 和 draft；失败保留 draft。
- 保存期间锁定编辑和退出。已提交后的运行应用失败报告“已保存，部分功能尚未应用”。
- 成功回执缺失或无法读取时禁用编辑、要求重新载入，不自动重发保存。
- 取消后结束当前编辑会话，重新读取数据库；关闭时有实际差异才提示放弃。
- 同会话重复显示保留草稿；不增加轮询、变更通知队列或自动合并。

配置量较小，提交一次完整的公开草稿更容易维护。宿主仍只写变化的字段或对象，避免不必要的 SQL、Qbar 注册表构建和索引更新。

## 4. 简化冲突处理

只使用主库已有的 `settings_revision`。事务内检查当前 revision 与编辑基线是否相同：相同则提交，不同则保留草稿并要求取消后重新载入。

这是明确的取舍：其他入口改了不同的配置项，也会拒绝本次保存。设置变更频率低，先采用这条简单规则；只有实际使用证明该限制影响体验时，才考虑更细的版本控制。

所有面向用户的设置写入入口必须在同一事务中增加 revision，包括托盘切换、快捷键绑定和鼠标速度配置。历史、笔记、聊天、统计及纯运行状态变更不增加该版本号。这个约束是简化冲突检查的前提。

不再维护逐字段、逐工具、逐窗口的三方比较函数，也不比较页面提交的基线或多个 profile stamp。

## 5. 控件与未来扩展

通用配置 schema 除类型和校验规则外，包含分组、名称、说明、控件类型、选项、展示单位及初始化默认声明。默认声明只由建库或明确的默认集版本升级写入数据库，不作为运行时缺失值兜底，也不由页面补值。这样字段规则、展示定义和初始化默认值只声明一次。页面使用少量统一控件：开关、文本、数字、下拉、密码及多行文本。

| 扩展 | 需要修改的位置 |
| --- | --- |
| 普通配置项 | 一处 schema 定义；按明确的默认集版本升级写入数据库 |
| 工具选项 | 该插件的 settingsSchema；值经 qbar_store 保存 |
| 新分组 | 分组元数据 |
| 特殊编辑方式 | 增加一个专用编辑器，仍读写同一份 draft |

快捷键、Tab 替换、工具列表和窗口绑定保留专用布局，不强行变成通用表单。工具里的普通字段直接复用统一控件，不再根据 Everything、剪贴板、搜索或运行工具身份分别生成相同控件。

## 6. 新工具与辅助操作

工具弹窗确认后只向本地 draft 加入一条记录。新记录使用 `draftId` 作为临时编辑标识，不是持久化 pluginId/commandId，也不能执行、记录历史或参与使用统计。

宿主统一保存时校验允许创建的工具类型，通过可信插件定义生成最终稳定 ID 并写库；保存后的重命名和别名变化不改变这些 ID。事务失败没有新记录，草稿保留。成功结果无法载入时重新读取主库，禁止自动再次创建。由此移除独立的“准备新工具”请求及跨请求暂存插件表。

窗口选择继续由宿主保留必要的选择令牌，验证新选择的窗口与进程身份；数据库仍只保存稳定目标描述。按键录制、程序选择、连接检查及密钥操作作为辅助服务，不维护第二套配置草稿。

## 7. 消息与职责

使用 WebView2 原生消息收发：页面 postMessage，宿主 PostWebMessageAsJson，页面单个 message 监听器分发已声明的消息类型。不再通过拼接 JavaScript 调用大量 window 全局函数。页面实现放在模块或闭包作用域内，避免同名全局绑定互相覆盖。

| 部分 | 职责 |
| --- | --- |
| 设置页面 | 控件、专用编辑器和唯一 draft |
| 设置服务 | 编辑会话、读取公开快照、最终校验、一次提交、结果生成 |
| 既有配置及功能仓储 | 各自的业务表读写，复用 AppStore 事务 |
| 选择、录制及连接服务 | 系统交互与结果返回 |

不引入通用配置框架、新的插件系统、消息重试队列或第二个数据库。暂不考虑旧消息协议和旧实现的兼容路径。

## 8. 实施边界与顺序

1. 统一公开配置模型和字段 schema，明确哪些字段进入 draft。
2. 建立单个消息入口和请求封装，替换旧回调协议。
3. 合并页面状态和提交服务；先保证全部设置写入入口正确更新 revision，再移除三方冲突分支。
4. 复用字段控件，保留专用编辑器；新工具改为保存时创建。
5. 清理失去调用的函数和字段，更新设计说明；不保留平行旧实现。

继续只使用 `data/capslock_p2.db`，保留既有用户配置、笔记、历史和媒体，不重建或清空数据库。开发不删除文件，不编写测试，不启动应用；AHK 修改必须进行 `/validate` 并检查全部警告。

- 有道、火山连接检查只为消息中明确提供的凭据建立覆盖项；`keep` 使用已保存值，`set` 使用草稿值，`clear` 使用空值。检查不写数据库，也不将已保存凭据传回页面。
