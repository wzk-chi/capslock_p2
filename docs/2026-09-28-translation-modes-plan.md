## 3. 产品行为

### 3.1 设置页

在“翻译共用配置”中保留引擎选择，新增“翻译方式”控件：

| 翻译方式 | 显示的语言控件 | 行为 |
| --- | --- | --- |
| 互译 | `语言 A [下拉框] ↔ 语言 B [下拉框]` | 原文为 A 时译为 B，原文为 B 时译为 A |
| 固定 | `目标语言 [下拉框]` | 始终译为所选目标语言 |

- 初始语言列表沿用当前支持项：`zh-CN`、`zh-TW`、`en`、`ja`、`ko`、`fr`、`de`、`es`、`ru`、`it`、`pt`、`ar`。
- 互译两端必须选择具体语言，不提供 `system` 或 `auto`。两个规范化语言代码不能相同。
- 固定目标保留 `system`，语义仍是 Windows 系统语言。
- 切换模式保留另一模式已选择的值，仅切换可见控件；不把隐藏字段清空。
- 语言 A/B 是对称的，交换它们不改变自动互译含义；设置页不需要额外的交换按钮，翻译面板的交换按钮按第 3.2 节处理。
- 首次提供的语言对预设为简体中文和英语；用户可以选择列表内其他组合。

### 3.2 翻译面板

- 固定模式显示一个由设置推送的“目标语言”下拉框（面板中只读），来源语言由引擎自动识别，不提供互译方向控件。
- 互译模式固定显示两个下拉框（通过无障碍标签区分原语言和目标语言），两个框的选项使用完整语言目录，且不能选择相同语言；初始值使用设置里的语言 A/B，两框居中放置，之间使用紧凑的图标交换按钮。
- 打开面板或载入新原文时，两个框先使用当前语言对的默认方向；点击翻译且用户没有手动选择时在 A/B 之间判断方向。能够区分时宿主把对应语言写入“原语言”框，把另一端写入“目标语言”框；无法区分时以语言 A 为目标，并显示固定回退说明。
- 用户手动改变任意一个下拉框后，本次请求转为手动方向；若两个框被选成同一语言，立即提示并阻止翻译。手动选择只作用于当前原文，不写入 INI。
- 点击“交换”按钮时，原语言和目标语言两个选项原子交换，同时把本次请求标记为手动方向；按钮不修改设置页保存的语言 A/B。交换后立即刷新方向提示和可翻译状态。
- 无法区分设置中的 A/B，或仅有数字／符号时，保留原文并以语言 A 为默认目标继续请求；页面显示方向未确定的说明。用户仍可改动下拉框或交换方向，切换为手动方向。
- 编辑原文、设置新的选中文本、改变模式或语言对时，清除本次手动方向并重新进入自动识别流程；如果用户再次选择下拉框或点击交换，则重新采用手动方向。
- 用户选好有效的原语言和目标语言后按 Enter 或点击“翻译”发起请求；Shift+Enter 保留换行，Ctrl+Enter 继续作为翻译快捷键。选择控件变化时不自动产生付费请求。
- 请求期间禁用原文、两个语言框、交换按钮和重复提交；完成、失败或取消时正确恢复。回退是有效方向，不进入等待手动选择状态。

### 3.3 边界规则

- 只在设置中的 A/B 之间判断，不尝试确定任意第三种语言。整篇使用同一个目标，不逐行互换。
- 使用 Windows ELS 候选排序，从中选取第一个匹配 A/B 的语言；候选为空时，全部文字只符合一侧的文字系统才据此选择方向。不维护词表，同文字系统和无法区分的混合文本不强行选择。
- 简繁中文作为两个输出选项保留。语言对只有一个中文选项时，任何中文标签都匹配该选项；语言对为 `zh-CN ↔ zh-TW` 时，若最先匹配的候选只有通用中文标签则无法区分，以语言 A 为目标回退并提示方向未确定。
- 文本属于已选语言对，但某个引擎不支持该语言代码时，显示明确的不支持提示；不得静默退回中文或其他语言。

## 4. 配置模型

统一保存在 `[TTranslate]`：

```ini
[TTranslate]
engine=auto
mode=fixed
languageA=zh-CN
languageB=en
targetLanguage=system
```

| 字段 | 允许值／用途 |
| --- | --- |
| `mode` | `fixed` 或 `bidirectional` |
| `languageA`、`languageB` | 上述具体语言代码；仅互译模式使用 |
| `targetLanguage` | 目标语言枚举，包括 `system`；仅固定模式使用 |
| `engine` | 保留 `auto`、`llm`、`youdao`、`volcengine` |

- 默认 `mode=fixed`，新默认配置同时提供 `languageA=zh-CN`、`languageB=en` 和 `targetLanguage=system`。应用只按新字段读取配置，不为旧 INI 提供特殊处理。
- 不实现旧配置迁移、字段映射、旧字段别名或旧值回退。使用新版本前，配置必须符合本节定义的新模型；缺少互译所需语言对字段时，互译模式配置无效并报告错误。
- 明确填写但非法的模式、语言代码或重复语言对须报告错误；缺省值与非法值分开处理。固定模式不要求使用中的语言对字段有效，但切换到互译前必须补齐并通过校验。
- 设置页保存时，将增量字段合并到当前 `TTranslate` 配置，再校验组合。有效模式为互译时验证 A/B 不同；固定模式允许保留暂时重复但未启用的语言对，重新启用互译时再校验。
- 字段本身是否合法由 `ConfigSchema()`／`ConfigValidateValue()` 校验，语言对关系由共享验证函数处理。前端提前提示，宿主仍执行校验。
- 跨字段校验必须发生在任何配置写入前；校验失败时整次提交不落盘。
- 请求入口重复校验有效配置，防止手工编辑 INI 绕过设置页约束。
- 保留设置页现有增量保存、冲突检测、取消草稿和外部配置刷新语义。

## 5. A/B 方向判断方案

2026-10-06 按用户要求只在设置中的 A/B 之间选择方向，并接入 Windows 官方 ELS 语言识别服务，替换手写词表；仅在候选为空时使用可区分 A/B 的文字系统作为辅助。无需额外网络请求、密钥或模型文件。

- 以 Microsoft Language Detection GUID `{CF7E00B1-909B-4D95-A8F4-611F7C377702}` 枚举系统服务，在进程内缓存服务描述和 DLL 句柄；枚举失败或没有服务时返回不可用。
- 用 `NormalizeString(NormalizationC)` 将输入规范化为 NFC UTF-16，再以 UTF-16 字符数调用 `MappingRecognizeText`，从索引 0 开始处理全文。输入字符串一直保留到属性包释放后。
- 官方语言识别服务返回一个结果范围，其中 `pData` 指向按相关性排序的 UTF-16 `MULTI_SZ` 语言标签。解析受 `dwDataSize` 的字节边界限制；首个字符为 NUL 即为空列表，允许仅 2 字节的结束符，非空列表再校验双零终止和标签格式。
- 从候选排序中选择第一个匹配 A/B 的标签，不与第三种语言竞争，也不把候选序号转换成百分比或置信度。非中文区域标签按主语言匹配，例如 `en-US` 匹配 `en`。
- 语言对只有一个中文选项时，任意 `zh` 标签都匹配该选项。简繁互译按 `zh-Hans`／`zh-Hant` 或对应区域标签匹配；通用 `zh` 同时匹配两边时回退，不再维护字形表。
- ELS 候选为空时移除数字、标点等非文字字符，检查剩余全部文字是否只符合 A/B 一侧的文字系统；例如中英的纯拉丁字母选择英语，汉字选择中文。两侧都符合（英法、简繁、纯汉字中日）或两侧都不完全符合（混合文字）时，保持不确定。此辅助不覆盖系统候选，也不掩盖接口失败。
- 仅有数字／符号、没有匹配候选且无法由文字系统区分、通用中文无法区分变体或系统调用失败时，以语言 A 为目标回退并提示可手动切换。

返回结构包含 `status`（`recognized`、`ambiguous`、`unsupported`、`unavailable`）、`language`（A、B 或空）、`reason` 和保持系统排序的 `candidates`。结果仅用于选择方向，不宣称已确定任意原语言。日志记录语言对、候选标签、状态、原因、方向及系统错误码；空结果补记输入字符数、结果字节数或空范围，不记录原文。

本机运行日志反馈：服务枚举成功（`count=1`、x64），一次中文请求返回 `zh`；用户反馈英文短词仍显示默认方向，同时间段的请求结果为 `dwDataSize=2`。旧解析器将该大小直接判为缓冲区错误，现改为检查首个 NUL 并正常处理空候选；补充文字系统辅助后仍须用户重载实际复核。

原生结构布局按官方声明和 Windows 默认对齐核对：

| 结构／字段 | x64 | x86 |
| --- | --- | --- |
| `MAPPING_ENUM_OPTIONS` 大小／`pGuid` 偏移 | 80／64 字节 | 40／32 字节 |
| `MAPPING_PROPERTY_BAG` 大小／结果范围指针偏移／范围数量偏移 | 64／8／16 字节 | 32／4／8 字节 |
| `MAPPING_DATA_RANGE.pData`／`dwDataSize` 偏移 | 24／32 字节 | 16／20 字节 |

每次成功识别后在 `finally` 中调用一次 `MappingFreePropertyBag`；进程退出时先关闭翻译面板，再用 `MappingFreeServices` 释放缓存，最后释放 DLL 句柄。固定模式和手动方向不调用识别服务。

官方依据：[服务及返回格式](https://learn.microsoft.com/en-us/windows/win32/intl/microsoft-language-detection)、[语言识别示例及生命周期](https://learn.microsoft.com/en-us/windows/win32/intl/requesting-text-recognition)、[服务枚举](https://learn.microsoft.com/en-us/windows/win32/api/elscore/nf-elscore-mappinggetservices)、[枚举选项结构](https://learn.microsoft.com/en-us/windows/win32/api/elscore/ns-elscore-mapping_enum_options)、[属性包结构](https://learn.microsoft.com/en-us/windows/win32/api/elscore/ns-elscore-mapping_property_bag)、[结果范围结构](https://learn.microsoft.com/en-us/windows/win32/api/elscore/ns-elscore-mapping_data_range)、[Unicode 规范化](https://learn.microsoft.com/en-us/windows/win32/api/winnls/nf-winnls-normalizestring)。ELS 桌面 API 的官方最低系统版本为 Windows 7；本机服务覆盖和短文本效果仍待运行确认。

本次完成官方契约和代码静态核对；AHK `/validate` 退出码为 0，且没有错误或警告，`git diff --check` 通过。按项目约束未执行项目代码，不宣称 `my name` 等输入的实际识别效果已验证成功。

## 6. 共享请求流程

建议在 `translate.ahk` 增加以下职责，函数名可随项目习惯微调：

- `TranslateLanguageCatalog()`：规范代码、语言名称、识别标签归一化所需元数据。后端目录作为页面语言选项来源，减少多处维护列表。
- `TranslateValidateOptions(options)`：模式与语言对跨字段校验，返回可展示的错误。
- `TranslateResolveDirection(text, options, sourceOverride, targetOverride)`：返回 `ready` 或 `error`；成功结果含具体 `sourceLanguage`、`targetLanguage`、方向、是否手动选择和 `fallback` 标志。
- `TranslateResolveRequest(...)`：将方向结果与选定 provider 合并为不可变的本次请求快照。

处理顺序：

1. 接收原文及可选 `sourceLanguage`、`targetLanguage` 和自动识别标记；宿主只允许语言目录中的代码，不信任页面传来的任意语言代码。
2. 截取当前配置快照并校验；固定模式忽略互译方向覆盖并解析 `system`。
3. 互译模式下，用户手动选择有效且不同的代码时直接采用手动方向；否则调用 A/B 判断。无法区分时以语言 A 为目标，并通过 `fallback` 标志在面板说明方向未确定。
4. 解析现有引擎选择；校验本次目标能映射到该引擎的官方语言代码。
5. 把实际目标通过 provider 已有的第四个 `overrides` 参数传入。合并覆盖值时保留原有凭据／模型等字段，避免改变 `TranslateSettingWith()` 的优先级。
6. LLM 提示词、有道 `to` 和火山 `TargetLanguage` 消费同一个已解析目标；引擎自身不重复识别互译方向。

请求生命周期要求：

- 在识别前生成请求代号，并绑定原文、配置、provider 和方向快照。
- 面板关闭、新原文到来、相关设置改变时，使旧代号失效；旧的识别结果、流式片段和完成回调不得更新新页面状态。
- LLM 复用现有中止机制；同步机器翻译无法中止网络调用时，至少在返回后丢弃失效结果。
- 所有分支都要收尾请求占用与控件状态，尤其是自动方向回退、provider 未配置和异常分支。
- 复用现有 `SetTimer` 延后请求调度；不在 WebView2 回调中同步创建 WebView2，不让循环变量闭包承担请求状态传递。
- 火山批量分行前只解析一次目标，所有批次共享该目标。

## 7. 三种引擎与提示词

- LLM：`TranslateLlmMessages()` 使用请求覆盖中的实际目标替换 `{{targetLanguage}}`。互译模式在请求中追加明确的本次目标约束，避免自定义提示词写死语言后忽略已选方向。约束使用语言目录生成的名称，不拼接用户原文为系统指令。说明自定义提示词仍应避免相互冲突，模型输出语言不能由客户端绝对保证。
- 有道：保留服务端自动识别来源；显式发送本次目标。不得依靠空目标或 `auto` 的服务端默认行为完成语言对逻辑。
- 火山：保留服务端来源识别，向所有批次传入实际目标；不得传入 `bidirectional`、`system` 等模式值。
- 核对官方支持语言表，补齐规范代码映射，尤其是 `zh-CN`、`zh-TW` 到各服务简繁代码的映射。当前转换函数会直接透传部分形似语言代码的字符串，不能据此认定服务端支持。
- 固定模式与互译模式都必须使用合法且受引擎支持的语言代码。显式非法或不支持的代码应报错；不能利用未知值的默认回退掩盖问题。
- 设置页已有“测试”按钮继续用于连接检查，不新增自动化测试。其固定 `Hello` 请求显式使用一个受支持的目标（如简体中文），绕过互译识别及语言对约束；说明它只确认连接，不验证互译质量。不得在开发期间点击或调用该按钮。
