# QBar 历史记录实施计划

日期：2026-09-28。

状态：已实施，未运行验证。本文档记录已落地的行为和静态验收范围。

## 1. 目标与已经确定的行为

用户希望在 QBar 输入为空时快速再次执行近期操作，包括命令和启动的应用，也包括 AI 问题、搜索词、Everything 查询、临时网址和路径。

| 项目 | 决定 |
| --- | --- |
| 保存数量 | 最多保留最近 10 条不同的记录 |
| 空输入展示数量 | 最多展示最近 10 条，与保存上限一致 |
| 重复操作 | 更新最近执行时间并移到最前，不重复占用名额 |
| 重启后的行为 | 从独立本地文件恢复记录 |
| 存储位置 | `%AppData%\capslock_p2\qbar-history.json`，AHK 使用 `A_AppData` 构建路径 |
| 时间顺序 | 最近执行的记录排在最前，不能被现有类型或字母排序打乱 |
| 一次性配置 | 不记录行内添加、覆盖配置等设置写入动作 |
| 查询内容 | 保留完整问题、关键词、路径和参数，不因为内容可能只使用一次而排除 |
| 兼容处理 | 不迁移旧格式，不保留旧消息协议分支，不实现历史格式兼容层 |
| 修改范围 | 新增历史模块并接入 QBar 执行、展示、重放与使用说明 |

历史记录最多保存并展示 10 条。本期不增加历史管理页面、更多历史入口、数量设置控件或清空按钮。

## 2. 项目约束

- AHK v2 实现放在 `lib/`，页面放在 `pages/`；`capslock-plus/` 仅供参考。
- 遵守根目录 `AGENTS.md`：禁止编写测试、启动或运行脚本、删除文件。
- 不运行 AHK `/validate`、重载程序、浏览器页面脚本或自动化交互检查。
- 使用现有 JSON、图标和 WebView2 宿主实现，不添加依赖。
- 页面沿用 `pages/theme.css`，不引入独立配色或主题切换逻辑。
- 历史正文不进入 `capslock_p2.ini`，不作为安装资源，不为本功能重新打包。
- 不自动提交或推送。提交需要单独的用户指令。
- 实施前重新读取 Git 状态及相关 diff。收集上下文时，`lib/features/everything/everything_panel.ahk` 已有未提交修改，必须保留。

## 3. 当前实现与接入依据

| 文件及函数 | 当前行为 | 实施要点 |
| --- | --- | --- |
| `lib/features/qbar/qbar.ahk`：`QbarShow` | 获取选中文本作为预填内容，每次显示重新报告行数 | 有预填文本时继续正常查询；只有空输入展示历史 |
| `lib/features/qbar/qbar_panel.ahk`：`QbarFinishIndexLoad` | 索引就绪后调用页面 `setInput`，触发查询 | 沿用现有加载时机，不另建一套打开页面的流程 |
| `lib/features/qbar/qbar_index.ahk`：`QbarQuery` | 去除首尾空格和制表符后，空字符串返回空结果 | 空分支改为读取最近 10 条历史 |
| 同文件：`QbarSendResults` | 仅发送 `short/label/type/pinned/icon` | 显式增加历史 ID、结果模式和请求 ID，不能假定额外字段会自动传到页面 |
| `pages/qbar.html`：`sortResults` | 按置顶、类型、标签排序 | 历史模式直接保留后端顺序 |
| 同页面：`execute` | 发送当前输入、选中项 short、类型与 Ctrl 状态 | 历史执行发送 ID，由 AHK 查找完整记录 |
| 同页面：`completeSelected` | 使用 row.short 补全输入 | 历史行必须提供可编辑的完整输入 |
| `qbar_commands.ahk`：`QbarExecute` | 按文本和选中类型分发，存在多个提前返回分支 | 各动作在确定完整执行内容后构建历史描述 |
| 同文件：`QbarRunBy` | 命中配置就返回 true，即使 Run 失败 | 返回值表示已处理，不能用作历史记录的成功标志 |
| 同文件：`QbarRunShortcut` | 先启动 lnk，失败时尝试 exe | 两条成功路径都要覆盖，每次用户操作最多记一次 |
| 同文件：`QbarOpenUrl` → `QbarOpenPath` | 网址规范化后交给通用启动函数 | 避免上下层分别记录，产生重复记录 |
| `lib/features/aiChat.ahk`：`AiChatShow` | WebView2 创建失败时提前返回，目前没有显式成功结果 | 补充成功结果，不能把函数正常返回等同于打开成功 |
| `lib/features/everything/everything.ahk`：`EverythingShow` | 当前已有打开成功/失败的布尔返回 | 复用返回结果；打开与实际搜索完成是不同阶段 |
| `lib/features/settings.ahk`：`SettingsShow` | WebView2 失败时返回，目前没有显式成功结果 | 为 QBar 打开设置记录提供明确结果 |
| `lib/app/config.ahk`：`ConfigAtomicWrite` | 通过相邻临时文件完整写入后替换目标文件 | 评估直接复用现有写入助手，不复制另一套临时文件实现 |

当前 QBar 没有执行历史。`QbarFutureStack` 以及参考版中的历史代码用于文件夹导航，不能复用为本功能的记录源。

页面与 AHK 宿主目前都允许最多 12 个可见结果行，展示 10 条历史不需要提高窗口行数上限。

## 4. 哪些操作进入历史

| 操作 | 是否记录 | 记录内容与成功边界 |
| --- | --- | --- |
| 开始菜单应用 | 是 | 应用名称、lnk 路径、exe 后备路径；任一启动路径成功 |
| QRun 配置命令 | 是 | 实际构建的完整 Run 命令，以及可编辑的触发词和参数；Run 未抛异常 |
| QWeb 配置网址 | 是 | 完整网址及入口文本；交给系统打开成功 |
| QSearch 搜索 | 是 | 搜索引擎入口、完整关键词及已替换的目标 URL；打开成功 |
| `web 网址`、直接网址、FTP | 是 | 规范化后的完整目标；打开成功 |
| 文件、文件夹，包括浏览结果中的选中项 | 是 | 拼接完成的完整路径；打开成功 |
| Ctrl+Enter 定位文件 | 是 | 完整路径及“在资源管理器中定位”动作；启动 Explorer 成功 |
| Ctrl+Enter 域名补全 | 是 | 最终打开的完整 URL；打开成功 |
| 显式 `ai/q 问题` | 是 | 实际交给 AI 页的完整问题；面板成功接收打开请求 |
| 裸 `ai/q` | 是 | 打开 AI 面板的空问题动作 |
| `e/everything/find/f 查询` | 是 | 完整查询及是否立即查询；Everything 页打开成功 |
| 裸 Everything 别名 | 是 | 打开工具入口，保留该入口现有的恢复页面状态语义 |
| `cl set/settings` | 是 | 打开设置页面；延迟打开成功后记录 |
| `键 ->类型 值` | 否 | 无论添加、覆盖、取消或失败，均不记录配置写入操作 |
| 仅选择搜索引擎并补全触发词 | 否 | 输入变更，尚未提交搜索 |
| Tab 补全、上下键选择、目录浏览查询 | 否 | 未执行目标动作 |
| 空白提交且没有可执行历史行 | 否 | 没有执行动作 |
| 未知 cl 子命令、启动失败、用户取消授权 | 否 | 不新增，也不更新旧记录时间 |

记录范围仅为从 QBar 发起的操作。AI 页内的后续对话、Everything 页内搜索和文件操作、其他快捷键启动的动作不自动汇入 QBar 历史。

AI 和 Everything 的成功边界是接收打开请求，不是模型回答成功或搜索结果返回成功。网络错误、无搜索结果或后续要求填写 AI 配置，不撤销已经接受的 QBar 历史。

## 5. 数据模型与去重

### 5.1 持久化结构

顶层对象只包含 `items` 数组，按最近到最旧排列。每项使用如下字段：

| 字段 | 含义 |
| --- | --- |
| `kind` | `run`、`shortcut`、`url`、`path`、`reveal`、`ai`、`everything`、`settings` 之一 |
| `label` | 结果行展示文字；应用用名称，查询类包含完整关键词或问题 |
| `input` | Tab 回填用的完整可编辑输入 |
| `payload` | 已解析的执行参数，只保存对应 kind 需要的字段 |
| `lastUsedUtc` | 最近一次成功执行时间，使用 UTC 时间字符串 |

示例：

```json
{
  "items": [
    {
      "kind": "everything",
      "label": "e ext:pdf 项目报告",
      "input": "e ext:pdf 项目报告",
      "payload": { "query": "ext:pdf 项目报告", "runQuery": true },
      "lastUsedUtc": "20260928120000"
    }
  ]
}
```

运行时为每条记录分配会话内稳定的 `historyId`，供页面选择使用。ID 不使用数组下标：记录置顶后，已有页面消息不能指向另一条记录。ID 和图标缓存不写入 JSON。

### 5.2 各种动作的载荷

| kind | payload 字段 | 重放行为 |
| --- | --- | --- |
| `run` | `command` | 直接执行保存的完整命令，包括原有引号、参数和 RunAs 信息 |
| `shortcut` | `shortcutPath`、`exe` | 复用 lnk 启动及 exe 后备逻辑 |
| `url` | `url` | 打开保存的最终 URL；搜索关键词已在 URL 中完成编码 |
| `path` | `path` | 打开保存的完整文件或目录路径 |
| `reveal` | `path` | 在 Explorer 中定位保存的目标；目录按现有逻辑打开 |
| `ai` | `question` | 直接交给 AI 页；允许空问题以打开入口 |
| `everything` | `query`、`runQuery` | 复用 EverythingShow 的实际接口，不把空输入误当成丢失的查询 |
| `settings` | `page` | 延迟打开指定设置页，本期为 general |

动作保存执行时解析出的目标。后来修改 QRun/QSearch/QWeb 配置，不会悄悄改变已有历史行的重放目标；Tab 回填后重新提交则按当前配置解析。这是本期确定的语义，不做配置变更后的历史迁移。

`input` 必须能够代表实际选中的动作。例如搜索应用时输入部分名称却选中了某个应用，历史回填使用应用完整名称；目录浏览时选中文件，回填使用完整路径。QRun、搜索和 AI 保留实际使用的参数，不能只存触发词。

### 5.3 去重规则

- 使用 kind 加固定顺序的 payload 字段作为动作身份；通过比较固定字段元组实现，不依赖 Map 的序列化键顺序。
- 相同问题通过 ai 或 q 发起时合并；相同 Everything 查询通过四个别名发起时合并。
- 不对问题、查询、命令参数或 URL 的路径部分统一转小写，不压缩内部空白，不截断多行问题。
- 同一 run 完整命令合并；不同参数分别保存。
- 同一 shortcut 路径合并；同名但路径不同的应用分别保存。
- `path` 和 `reveal` 是不同动作，不能相互合并。
- QRun 与开始菜单启动属于不同 kind，不做跨类型程序身份推断。
- 每次执行成功：确保历史已加载 → 查找同身份项 → 更新或插入到数组首位 → 裁剪为 10 条 → 保存。
- 数组顺序是最终展示依据，时间仅作记录，不依赖时间精度区分连续操作。

## 6. 历史模块及存储生命周期

新增 `lib/features/qbar/qbar_history.ahk`。建议提供以下职责明确的接口，具体签名可随实现微调：

| 接口 | 职责 |
| --- | --- |
| `QbarHistoryEnsureLoaded()` | 每个程序会话只加载一次，恢复最多 10 条记录并生成运行时 ID |
| `QbarHistoryValidateEntry(entry)` | 校验 kind、字段类型及对应载荷，忽略无效项 |
| `QbarHistoryIdentity(entry)` | 生成用于精确去重的固定字段元组 |
| `QbarHistoryRemember(entry)` | 成功后更新最近记录；自身处理存储异常 |
| `QbarHistorySave()` | 将允许持久化的字段保存到独立 JSON 文件 |
| `QbarHistoryRows(limit := 10)` | 生成页面需要的历史行，并复用图标来源 |
| `QbarHistoryReplay(historyId)` | 按稳定 ID 查找并执行完整动作 |

状态集中在新模块内，包括 `QbarHistoryLimit := 10`、`QbarHistoryDisplayLimit := 10`、加载标志、数组、运行时 ID 计数器。不借用 `QbarFutureStack`，不在 QbarHide 时清空历史。

加载与保存要求：

1. 首次查询历史或首次记录前加载，防止第一次写入覆盖已有记录。
2. 文件不存在时使用空数组；加载本身不自动创建文件或启动任何记录。
3. 根对象或 JSON 损坏时使用空历史；格式正确时跳过个别无效记录，并对有效记录去重、截取前 10 条。
4. 不因为读取失败立即重写文件；下一次成功的用户操作才尝试保存有效的内存历史。
5. 写入前确保专用目录存在，使用项目现有 JSON 库和可复用的完整写入后替换机制。
6. 保存失败时保留内存记录。异常不能向外传播到启动动作的 try/catch，否则会出现“应用已启动却提示无法运行”的错误反馈。
7. 日志仅记录失败类别，不写入历史 JSON、完整命令、问题、URL 或路径正文。
8. 不新增历史文件清理、备份迁移、多实例合并或后台监视逻辑。程序已有 SingleInstance 约束。

## 7. 记录与重放的执行边界

### 7.1 共用实际动作，分开配置解析与重放

在 `qbar_commands.ahk` 中建立轻量的“执行已解析动作”入口，普通 QBar 分支和历史重放共用这个入口。配置匹配、快捷键优先级和输入解析仍由现有 QbarExecute 路径负责。

该入口接收完整动作描述，复用现有启动函数，获得明确的执行成功结果，并在成功后只调用一次 QbarHistoryRemember。历史重放不能再通过空输入加 search/everything 类型走旧的选择分支。

允许对启动函数增加成功结果或拆出返回布尔值的内部动作函数，但必须保留 QbarRunBy 的“是否命中并处理”返回语义，避免启动失败后继续落入 AI 兜底。

### 7.2 避免漏记和重记

- QbarExecute 中每个 Everything 提前返回、AI 行、AI 别名及兜底分支都要覆盖。
- QbarRunShortcut 的 lnk 成功与 exe 后备成功汇合到同一个记录点。
- QbarOpenUrl 调用 QbarOpenPath 时只在动作边界记录一次。
- QbarLocateInExplorer 打开目录时也不能与 QbarOpenPath 重复记录。
- 失败重放保留原记录原位置，不置顶、不删除，不把错误追加为历史。
- 同一动作从别的功能调用底层启动函数时，不自动写 QBar 历史；是否记录由 QBar 动作入口决定。

### 7.3 面板打开与异步回调

- EverythingShow 已有明确返回值，直接使用并核对其两个参数的现有语义。
- AiChatShow 和 SettingsShow 增加显式的打开成功/失败返回值；只补充结果，不更改现有页面行为。
- `cl set/settings` 的记录放在延迟执行函数中，不能在 SetTimer 排队时提前当作成功。
- WebView2 消息回调继续用 SetTimer 延迟执行，禁止在回调中同步创建另一个 WebView2。
- 延迟函数通过 Bind 传递动作数据，不依赖 for 循环变量闭包，也不使用全局“当前待记历史”槽位，以免并发覆盖。

## 8. 前后端消息和展示

### 8.1 普通查询与历史查询

在 QbarQuery 中，沿用去除首尾空格和制表符的空输入判定。空输入返回历史模式；非空输入沿用普通查询。

页面增加明确的 `resultsMode`，取值为 `normal` 或 `history`。QbarSendResults 和 window.setResults 同步更新调用约定，不保留新旧协议兼容分支。所有调用位置一起修改。

历史行发送：`historyId`、`short`（完整可编辑 input）、`label`、原有视觉类型、`icon`。完整执行载荷留在 AHK 端，页面只需要 ID。

### 8.2 防止旧结果误执行

页面为每次 query 分配递增 queryId；AHK 保留现有 QbarQuerySeq 失效机制，并将页面 queryId 原样放入结果消息。页面只接受与当前查询匹配的结果。

每次输入变化立即取消当前历史行的可执行状态，等待匹配的新结果；中文输入法 compositionstart 时也取消旧行选择，compositionend 后发起查询。

历史执行使用独立消息 `executeHistory`，携带 historyId 和 queryId。AHK 核对当前 QBar 可见、最新查询是空输入、请求代次匹配、ID 仍属于当前展示历史后，再延迟执行重放。延迟执行入口再次检查代次，避免关闭或更改输入后执行旧消息。

查询序号、数据行索引和 historyId 各司其职，不能用数组下标替代稳定 ID。

### 8.3 页面操作

- 历史模式保持 AHK 顺序，普通模式继续使用现有排序。
- render、select、completeSelected 和 execute 使用同一个结果顺序函数，避免视觉选中行与实际执行行不同。
- 有历史时默认选中第一条；上下键循环选择；点击和 Enter 重放。
- 历史模式下 Ctrl+Enter 与 Enter 一样重放所选动作，不临时将历史解释为域名或改变原动作。需要修改动作时使用 Tab 回填。
- Tab 回填完整 input，焦点和光标移到末尾，发起普通查询，不在回填时记历史。
- 历史模式下 `/`、`\` 按普通输入字符处理，避免现有路径补全逻辑自动替换成第一条历史；普通模式保持现有行为。
- 无历史时保持空列表，不填充推荐项，不制造占位历史。
- 隐藏列表、重新打开 QBar、清空输入后重新展示时，要正确恢复选择、模式和行数报告。
- 图标仍按原有类型及目标路径生成，通过现有图标队列增量发送；显示文字继续用 textContent。
- 沿用原有主题和行高，不增加独立样式主题。长内容视觉截断但存储和重放保留全文。

## 10. 静态验收清单

以下为人工代码审查标准，不编写或执行测试脚本，不启动程序验证这些场景。

| 场景 | 代码必须保证的行为 |
| --- | --- |
| 没有历史文件 | 返回空历史，空输入列表收起 |
| 已存 10 条 | 加载最多 10 条，并向默认历史列表发送这 10 条 |
| 第 11 个不同动作成功 | 新动作置顶，内存和持久化数组均最多 10 条 |
| 相同动作再次成功 | 更新现有记录并置顶，数量不增加 |
| 相同命令不同参数 | 两条记录分别保留 |
| 不同别名、同一个 AI 问题或 Everything 查询 | 合并同动作；保存最新的展示与回填文本 |
| 应用选中项与输入片段不同 | 重放选中的应用；Tab 回填可执行的完整名称 |
| QRun 启动失败 | 保持原处理返回路径，不记录，不落入 AI 兜底 |
| lnk 失败、exe 后备成功 | 只新增或更新一条应用历史 |
| search 历史在空输入下执行 | 打开原完整搜索 URL，不停留在补全触发词 |
| Everything 历史在空输入下执行 | 保留完整查询与执行模式，不变成空查询 |
| AI 问题含中文、引号、换行 | JSON 往返和执行参数保持完整，展示使用纯文本 |
| 文件夹浏览后选择文件 | 保存完整路径，不只保存叶子名称 |
| Ctrl+Enter 定位与普通打开 | 记录为不同操作，后续可以分别重放 |
| 行内配置成功、覆盖或取消 | 所有路径均不写历史 |
| 仅补全搜索引擎、Tab 或路径导航 | 不写历史 |
| 面板打开失败 | 不新增或置顶；延迟排队本身不算成功 |
| AI 后续网络失败或 Everything 无结果 | 不撤销已经成功接受的 QBar 打开请求 |
| 存储不可写 | 动作仍成功，内存记录保留，不报告成启动失败 |
| JSON 损坏或记录字段缺失 | 按加载规则降级，普通 QBar 查询与启动仍可用 |
| 过期历史 ID、旧 queryId 或窗口已隐藏 | 丢弃执行请求，不执行其他行，也不进入普通文本兜底 |
| 展示历史后立即输入或开始 IME 组合 | 旧历史选中状态失效，不能误执行第一条历史 |
| 图标异步到达后重绘 | 历史顺序和选中 ID 保持一致 |
| 重新打开 QBar 或清空输入 | 重新查询当前历史，正确恢复行数报告和列表状态 |
| 检查最终 diff | 未修改参考子目录、个人配置或无关 Everything 面板内容 |

静态审查可以确认分支覆盖和数据流，不能证明 AHK 运行、WebView2 交互、文件系统写入或系统启动行为已经通过验证。最终说明必须保留这一限制。
