# AI 问答多会话设计

日期：2026-10-05

状态：已实现。遵循仓库约束，本次未启动程序、脚本或测试。

## 1. 目标与范围

为 AI 问答增加独立数据库和持久化会话管理。用户每次重新打开面板时进入空白新会话；可查看历史、切换、重命名、单条删除和多选删除。新会话的标题由首个问题单独调用 AI 生成。

本设计沿用现有 `[LLM]` 连接配置、`[QAI]` 问答提示词、AI 流式回答、SQLite 绑定、WebView2 面板和共享页面主题。会话正文不写日志。当前数据库文件不额外加密，数据由安装目录权限保护；更换安装目录时由用户迁移对应数据目录。

## 2. 现有基础

- `lib/features/aiChat.ahk` 维护问答历史和流式请求状态；当前内存与页面最多保留 50 轮。
- `lib/shared/llm.ahk` 提供异步 `LLMChatStream()`，适合回答和标题生成；同步 `LLMChatComplete()` 会阻塞调用方，不用于标题生成。
- `lib/vendor/CSQLite.ahk` 和 `resources/SQLite3.dll` 已提供 SQLite、参数绑定和事务能力。
- 笔记和剪贴板历史数据库都放在安装目录 `data/` 下；安装目录需要可写，运行数据不列入安装包，也不由卸载流程删除。
- WebView2 页面使用 `pages/theme.css`、`pages/toast.js` 和 `pages/dialog.js` 的共享样式与交互。

## 3. 模块边界

```text
pages/chat.html
    ↕ 会话命令、列表和消息视图
lib/features/aiChat.ahk
    ├── lib/features/aiChat_store.ahk ── data/ai-chat/ai-chat.db
    └── lib/shared/llm.ahk ──────────── 回答和标题请求
```

- `aiChat_store.ahk` 独占数据库访问，负责初始化、版本迁移、会话和轮次读写、排序、重命名及事务删除。
- `aiChat.ahk` 持有当前会话、页面代次、请求身份和 LLM 请求生命周期；每个持久化操作通过 store 完成。
- `chat.html` 发送用户操作并展示宿主结果。会话 ID、消息 ID 和版本信息都按不可信输入校验；页面不传 SQL、文件路径或函数名。
- 在 `capslock_p2.ahk` 中先引入 store，再引入 `aiChat.ahk`。

## 4. 数据位置与结构

运行时数据库路径：

```text
{安装目录}\data\ai-chat\ai-chat.db
```

该目录不加入 Inno Setup 的 `[Files]` 或卸载清理项。覆盖更新保留数据；更换安装目录时用户复制整个 `data\ai-chat` 子目录。数据库目录无法创建或写入时向用户显示清楚的提示，并将错误细节写入日志；不得自动删除、重建或迁移已有数据库。

实现使用两张表，以一条轮次记录同时关联问题和回答：

| 表 | 字段 | 用途 |
| --- | --- | --- |
| `ai_chat_sessions` | `id`、`title`、`title_state`、`created_at`、`last_chat_at` | 会话元数据；标题状态为 `pending`、`auto`、`fallback` 或 `manual` |
| `ai_chat_turns` | `id`、`session_id`、`ordinal`、`question`、`answer`、`answer_status`、`created_at`、`completed_at` | 一组问答；回答状态为 `generating`、`complete`、`interrupted` 或 `failed` |

`session_id` 设置外键级联删除，`(session_id, ordinal)` 唯一。历史按最后聊天时间 `last_chat_at DESC, id DESC` 排序；置顶会话排在普通会话前，同组内仍按最后聊天时间倒序。用户提交问题、回答完成或轮次中断时更新 `last_chat_at`；标题生成和手动重命名不改变它。为 `last_chat_at`、`(session_id, ordinal)` 建索引。用 SQLite `user_version` 管理 schema，启用外键和 busy timeout，用户输入通过绑定参数保存。

## 5. 生命周期与保存规则

1. 面板从隐藏变为显示时创建空白、尚未入库的会话。用户显式点击“新会话”也执行同样重置。再次激活已显示的窗口、页面加载完成或设置变更不得重置当前会话。
2. 用户发送首个问题时，先在单个事务中创建会话、写入轮次和待命名标题；保存成功后才发出主回答请求。空白会话不保存。
3. 主回答流式输出时，内容保存在当前请求缓冲区，并按约 1 秒节流检查一次数据库状态和保存进度；收到完成、失败或取消结果时立即写入最终状态。错误信息不保存为模型回答。
4. 失败和中断的问题保留在会话中，并明确标记“回答未完成”。模型上下文只包含已完成轮次和当前问题，历史的未完成回答不会被当作有效上下文。
5. WebView 页面重新创建时，宿主根据当前会话 ID 重新加载状态。用户下次重新打开已隐藏的面板时仍从空白新会话开始，历史通过会话列表访问。
6. 首次保存失败时不发送主回答请求；后续回答保存失败时保留内存中的答案，允许重试本地保存，不重复调用 LLM。

新建会话的第一轮即使回答失败，问题仍属于该会话并参与自动命名。用户之后可在该会话继续发送新问题；失败轮次不会进入后续模型上下文。

## 6. 自动命名

- 每个新会话只为首个问题安排一次独立标题请求；不发送回答、后续轮次或完整历史。
- 标题请求使用专用系统提示词和首个问题。禁用思考模式，要求用当前界面语言生成简短标题，并在宿主侧去除换行、前后引号和多余标点，限制最终标题长度。
- 使用异步流式请求收集标题，不阻塞页面。为了优先处理问答请求，在首轮主请求完成、失败或取消后再调度标题请求。
- 创建会话时先把首个问题压缩成临时标题，`title_state` 设为 `pending`。生成失败、空结果或超时则保留该标题并标记 `fallback`。
- 手动重命名把状态改为 `manual`。标题回调只在数据库记录仍存在且状态仍为 `pending` 时更新；删除或重命名之后的迟到回调不能重建或覆盖记录。
- 每次请求只记录操作阶段、状态和耗时，不记录问题、回答、标题、密钥或 endpoint 查询串。

## 7. 页面与交互

左侧边栏默认折叠。边栏上方的折叠/展开控件是结构控制；折叠状态只显示两个操作按钮图标：“新建对话”和“设置”，两者仍可直接点击并提供可访问名称。展开后显示这两个按钮的文字名称，下面是“会话历史”标题和历史列表。打开或收起边栏不切换或重置当前会话。

“会话历史”标题右侧的多选按钮切换选择模式。选择模式中每个会话项出现复选框，底部显示已选数量和批量删除操作；删除前确认，范围仅为已勾选项。列表分页时，“选择当前已显示项”只选当前加载的会话，不扩大到数据库中的其他记录。

普通模式下，右键会话项打开菜单，提供“重命名”“置顶”“删除”。菜单靠近目标项显示并避开边界；支持键盘菜单键和 Shift+F10。置顶会话排在普通会话之前，同组再按最后聊天时间倒序排列。

列表每行显示标题、最近活动时间和当前会话标记。历史会话列表按活动时间分页，每批建议 50 条。打开会话时先加载最近 100 条消息，向上滚动再加载更早内容，并保持滚动锚点。数据库保存完整对话；模型仍只使用最近 50 轮并遵循现有 token 预算。

重命名复用 `AppDialog.prompt()`，单条和批量删除复用 `AppDialog.confirm()`；页面提示复用 `AppToast`。所有文字、状态、控件和模态样式遵循共享主题。按下 Esc 时先让活动对话框处理，再关闭历史栏，最后才关闭面板。

删除操作以事务执行。只有提交成功后才刷新列表和清空内存状态；删除当前会话后显示空白新会话。列表查看和删除不依赖 LLM 配置，未配置 API 时用户仍可管理历史。

## 8. 异步身份与过期消息

- 每次页面创建或切换视图时递增 `viewGeneration`；页面命令和宿主回复携带该代次，旧页面的迟到命令或结果直接丢弃。
- 页面加载后由宿主发送初始化状态（含 `viewGeneration`、语言和当前会话）；页面收到后才启用会话操作并回传代次，避免新页面在初始化前发出过期命令。
- 主请求绑定 `sessionId`、`turnId`、`requestId` 和 `viewGeneration`。切换、新建、删除或隐藏时，先使旧请求失效，再取消流并保存其轮次状态。
- 标题任务按 `sessionId` 独立跟踪。切换当前会话不取消其他会话仍有效的标题任务；会话删除会使对应标题任务失效。
- WebView 回调只做消息解析和状态登记，耗时工作通过现有异步 LLM API 或延迟调度执行。所有页面消息及数据库 ID 都需要宿主校验。

## 9. 错误处理与安全

- 数据库初始化、读、写、提交失败时记录安全的技术信息，并向用户说明数据暂不可用及下一步。API 未配置时仍能查看和整理已有会话。
- 数据库版本高于程序支持版本时保留文件并提示用户升级程序；迁移失败时回滚，不把历史页面显示成空列表。
- 页面以 `textContent` 展示用户文本和标题；AI 回答沿用现有 Markdown 清洗路径。数据库写入使用参数绑定，批量删除只接受宿主验证过的会话 ID。
- 用户问题和回答已按当前问答功能发送给用户配置的 LLM 服务。数据库保存在本地，首版不增加本地加密机制。

## 10. 实现完成条件

- 每次重新打开面板默认进入空会话，历史列表可访问已保存会话。
- 会话可切换、续聊、单条重命名、单条删除和多选删除；删除当前会话后视图为空。
- 新会话用首个问题进行一次独立异步命名；失败时显示问题生成的短标题，手动命名不会被迟到结果覆盖。
- 请求失败、中断、页面重建、数据库写入错误和删除期间的迟到回调不会污染其他会话或丢弃已提交的历史。
- 运行数据路径与安装包清单、卸载清理规则保持分离；开发实施遵守仓库对测试和脚本运行的限制。
