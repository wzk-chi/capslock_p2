## 1. 需求与本轮范围

增加剪贴板历史功能，程序运行期间自动记录用户复制或剪切的内容，重启程序后仍可查询和再次使用。首版支持文本、图片、文件/文件夹，以及常见 HTML/RTF 富文本。

用户已明确的交互要求：

- 页面参考提供的剪贴板截图，以左侧历史列表为主体。
- 上方提供搜索、类型筛选和收藏筛选。
- 单击列表项复制；双击列表项粘贴。
- 列表项右键菜单包含：查看、复制、粘贴、收藏、删除；已收藏项显示“取消收藏”。
- 下方固定操作按钮 bar，包含“清空”；确认后清空全部未收藏历史，保留所有收藏。
- CapsLock+Z 作为快捷入口；QBar 输入“剪贴板历史”或 `cv` 可搜索并打开该工具。
- 本期不实现参考图右侧的竖向操作按钮。

实现遵守 `AGENTS.md`：AHK v2 功能放在 `lib/`，页面放在 `pages/`，不编写测试、不启动或运行脚本、不删除文件、不自动重新打包；实现保留了工作区已有修改。运行验证需在后续允许启动程序时单独进行。

入口按键、QBar 搜索词和收藏保留规则已由用户确定。下文的容量参数和窗口尺寸仍是设计建议，可在评审时调整；上述用户要求作为实现验收依据。

## 2. 现有实现与复用边界

| 现有模块 | 已有能力 | 本功能的接入方式 |
| --- | --- | --- |
| `lib/app/core.ahk` | `OnClipboardChange`、`ClipboardAll()`、剪贴板序号、系统/两组独立槽位 | 统一挂起计数和 reason；公共回调先登记历史通知，槽位快照完成后供历史复用 |
| `lib/input/keys.ahk`、`keymap.ahk` | CapsLock 层、普通 Ctrl+V 拦截、配置动作分派 | 新增历史窗口动作；恢复历史时同步系统槽位状态 |
| `lib/shared/panelHost.ahk` | WebView2 生命周期、窗口显示/隐藏、事件解绑 | 新页面直接复用，不另外维护一套宿主 |
| `lib/shared/windowBar.ahk`、`pages/windowbar.js` | 面板窗口栏 | 延续项目统一窗口行为 |
| `lib/vendor/CSQLite.ahk`、`resources/SQLite3.dll` | SQLite 连接、事务、元数据查询 | 复用库和 DLL；二进制参数绑定使用 SQLite 官方 C API |
| `lib/features/qbar/qbar_plugin_catalog.ahk` 等 | 内置工具注册、别名、面板命令执行 | 增加剪贴板工具入口，正文仍由历史服务管理 |
| `lib/features/qbar/icons.ahk` | GDI+、PNG 编码、Shell 图标 | 复用合适的图像/图标基础接口，缩略图转换单独管理生命周期 |
| `pages/theme.css`、`dialog.js`、`toast.js`、`icons.js` | 共享主题、确认框、反馈和图标 | 页面复用，局部 CSS 只管理布局和尺寸 |

当前多剪贴板只是内存中的三个最新快照，没有历史列表。QBar 的 `command_history` 是命令执行历史，不承载剪贴板内容。

AHK 官方支持 `ClipboardAll()` 二进制快照的保存与恢复，以及从符合公开结构的 Buffer 创建 `ClipboardAll(buffer)`。历史只保存白名单数据：优先从同序号的既有槽位快照提取，无可复用快照时才自行按白名单读取。历史服务不为记录额外调用无参数 `ClipboardAll()`。现有独立槽位和临时选区仍有全量快照开销，其来源/挂起管理需要统一迁移，但本设计不将这种开销宣称为已消除。持久化还需处理注册格式编号与文件剪切的移动语义。

本设计采用独立历史数据库，复用 SQLite 基础设施。持续记录的大体积数据、收藏和清空操作因此拥有单独生命周期，不与 QBar 配置、命令历史、笔记资产关联。

## 3. 入口和窗口

- 新增 `keyFunc_clipboardHistory`，默认将当前空闲的 `caps_z` 绑定到该动作，即 CapsLock+Z 打开/隐藏历史窗口。
- 保留个人 `[Keys]` 覆盖机制，升级时不强行改写用户已有 `caps_z`。
- QBar 新增内置工具 `builtin.clipboard`，显示名称“剪贴板历史”，默认别名 `cv`、`剪贴板历史`；名称和别名均进入现有搜索索引，输入任一搜索词都显示同一个工具项。别名冲突沿用现有插件机制处理。
- 输入 `cv` 或“剪贴板历史”后，选择该工具并按 Enter 打开独立历史面板；`cv 关键词` 或“剪贴板历史 关键词”可预填面板内搜索。QBar 中可以记录“打开剪贴板历史工具”，不把历史正文写入命令历史。
- 无需打开面板即可持续记录；启动时初始化历史服务，WebView2 首次打开时再创建。
- 建议窗口初始为约 860 × 640 逻辑像素，可缩放，复用 `ScreenFitSize()` 和现有 DPI 处理；最小约 560 × 360，实际不超过工作区。
- 快捷键打开时捕获当前前台外部窗口 HWND 与进程 ID，保存为本次粘贴目标。由 QBar 执行工具时，在执行入口、`QbarHide()` 之前重新读取前台：当前是有效外部窗口则采用该窗口；仅当前台确实是 QBar 时，才回退到该 QBar 会话的最近外部目标上下文。不得无条件沿用打开 QBar 时的 `QbarTargetHwnd`。
- QBar 会话内补上前台变化记录：观察到外部窗口切换时同步最近目标的 HWND、进程 ID 和会话标记。用户转到别处又回到 QBar 时不能仍沿用旧目标；若跟踪发生断档、上下文失效或当前前台是其他本程序面板，不选取旧窗口，历史面板按无可信粘贴目标打开。单纯“HWND 仍属于同一进程”不能证明它是用户本次期望的目标。
- QBar 入口选定的目标上下文在隐藏 QBar 和排队创建历史面板之前冻结，通过 `Bind()` 传递；面板创建后的前台通常已经是本程序窗口，不能此时重新猜目标。快捷键和 QBar 路径最终使用同一目标校验入口。
- 在面板内部打开菜单、确认框、搜索或改变筛选时，粘贴目标不变。从另一外部窗口再次唤起时更新目标；面板已在前台时不覆盖为自己。
- 单击复制保持窗口打开；粘贴先激活并验证外部目标，再隐藏面板。激活失败不隐藏；隐藏后的写入或发送失败必须恢复可见并反馈。关闭和隐藏不停止记录、不清空数据。
- 使用现有统一窗口栏；面板默认不因临时失去焦点自动隐藏，避免右键菜单和确认操作中断。Esc 优先关闭确认框/菜单，再关闭面板。

### 4.1 搜索和筛选

- 类型为互斥选项：全部、文本、图片、文件。富文本归入“文本”，行内显示“富文本”标签，保留 HTML/RTF 格式。
- “收藏”是独立开关，可与任一类型和搜索组合。例如“图片 + 收藏 + 关键词”。再次点击收藏恢复同类型下的全部记录。
- 收藏按钮显示全部收藏数量，不随搜索条件缩减；底部显示全部记录数和当前条件下的匹配数，不把已加载数量当作匹配总数。
- 搜索按内容子串匹配：文本/有纯文本后备的富文本搜索完整可读文字，文件搜索文件名和完整路径，图片搜索保存的文字说明（如有）及“图片”类型标题。没有可读后备的富文本仍保留原格式，首版只能按类型标题检索，预览显示“富文本（无文字预览）”。
- 首版不做 OCR，不读取文件正文、不遍历文件夹、不访问网络以补全富文本资源。
- 搜索输入建议 150ms 防抖；IME 组合输入期间不查询，`compositionend` 后立即查询。清空搜索仍保留类型/收藏筛选。
- 查询统一在 AHK/数据库端执行。参数使用绑定，`%`、`_` 等字符按字面处理；不把输入解释为 SQL 或正则。
- 新一轮搜索、筛选、关闭或重开面板产生新查询 ID，过期响应不覆盖当前列表。

### 4.2 列表项

| 类型 | 主内容 | 次信息 | 复制/粘贴内容 |
| --- | --- | --- | --- |
| 文本 | 原文前 240 字符，保留换行和缩进；自动折行，多行预览最多显示 14 行 | 相对复制时间、字符数 | 完整文本，保留内部空白和换行 |
| 富文本 | 可读文字预览及“富文本”标签 | 相对复制时间、字符数、格式标识 | 可用的 HTML/RTF 和纯文本后备 |
| 图片 | 按比例缩略图，建议最大约 180 × 96，使用 contain | 相对复制时间、原始宽 × 高 | 保存的原始图片格式，缩略图不用于粘贴 |
| 文件 | 文件图标、前几个文件名，多文件显示“另 N 项” | 相对复制时间、项目数 | 一组文件/文件夹路径的真实 CF_HDROP |

相对时间基于最近一次真实捕获时间，tooltip 提供准确本地时间。文件列表只展示已保存的名称、路径和数量；首版不主动探测源路径，不能把未经检查的文件标为“已失效”或“可用”。文件 tooltip 提示“保存的是原路径；是否可用由粘贴目标处理”，历史仍可收藏或删除。

空历史与筛选无结果分别显示“暂无剪贴板历史”和“没有匹配的历史”。数据库失败、图片预览失败、容量已满各有明确状态，不伪装为空列表。

选中项显示共享主题的边框/底色。行内收藏星标是独立按钮，点击只改变收藏状态，必须阻止冒泡，不能触发复制或双击粘贴。

## 5. 列表操作

### 5.1 单击复制与双击粘贴

单击主内容区选中该项并立即复制完整内容，成功显示共享 toast“已复制”，保持面板打开。只有写入系统剪贴板成功才显示成功。

文件项拖出使用 Windows Shell 原生拖放，仅提供 `CF_HDROP` 文件组；图片项原生拖出只提供保存的 PNG/DIB 图像格式。两者都不把路径、链接或预览文本当作替代拖放数据；原生拖放初始化失败时明确失败，不回退为文本拖动。剪贴板历史面板不接收外部拖放，防止拖入的文件在 WebView 中被打开或预览。

双击的浏览器事件序列通常是 `click(detail=1)`、`click(detail=2)`、`dblclick`：

1. 第一次 click 按单击语义复制。
2. 第二次 click 不再次复制。
3. dblclick 只提交一次粘贴动作；该动作仍自行校验记录并准备剪贴板，不能依赖第一次复制必然成功。提交 dblclick 本身不隐藏面板，隐藏时机由 §5.2 的激活确认结果决定。

复制不重排列表、不替换整块 DOM，确保第二次点击仍命中同一行。操作始终捕获稳定记录 ID；异步新增、筛选响应或删除不能将当前动作改成别的行。第二下与第一下的 ID 不一致时不按原项粘贴。

复制成功不改变最近捕获时间，不重新新增历史。双击期间合并复制反馈，不先闪出一个成功提示又重复提示两次。

同一会话的剪贴板写入动作串行协调。双击粘贴收到后，取消第一下复制尚未执行的重试；已执行的复制结束后才能开始粘贴。任一重试携带操作代次并检查当前序号，过期复制不能在粘贴或用户新复制之后再次写入剪贴板。

上下键只移动选中状态；Enter 粘贴选中项，Ctrl+C 在列表聚焦时复制选中项。搜索框中的 Ctrl+C、方向键和文本选择保持输入框行为。图像、文件和文本行均使用相同操作入口。

### 5.2 粘贴

“粘贴”用于发送到本次打开面板前的外部目标窗口：

1. 固定记录 ID、面板会话 ID、可信目标上下文；从 AHK 存储读取完整载荷，预先完成格式校验和必要缓冲区准备。该阶段面板保持可见。
2. 校验路径列表结构和目标窗口身份，确认 HWND/进程 ID 与可信上下文一致且不是本程序面板；不访问源文件以检查其存在性。
3. 面板仍可见时激活目标，并建议最多等待 0.4 秒；只有 `WinWaitActive` 和当前前台 HWND 都确认成功，才允许进入隐藏阶段。期间不启用失焦自动隐藏，不能用“先藏起来才能激活”替代确认。
4. 在同一已授权动作中隐藏面板；隐藏后再次核对前台目标和动作代次。前台改变或动作取消则停止，不写入、不发送，并恢复面板可见。
5. 写入完整剪贴板载荷、同步系统槽位，再核对前台与本次写入序号，发送一次 `Ctrl+V`。写入失败、发送调用失败或发送前目标/序号变化时，恢复面板可见并报告失败；不能留下已经隐藏但按键没有发出的静默状态。
6. 成功写入的内容保持为当前系统剪贴板，不延时恢复旧值。图片和文件可能被目标异步读取，恢复旧值容易使粘贴失效。

降级语义：没有可信目标、目标消失或激活失败时，不隐藏面板、不发送按键，可尝试复制供手动粘贴。只有该次复制确实成功才提示“已复制，请切换到目标窗口粘贴”；若复制也失败，显示“复制失败，未发送粘贴”。载荷损坏不能降级成成功复制。

失败可见性分两个边界：隐藏前失败保持可见；隐藏后失败恢复可见。恢复保留搜索、筛选和选中项，并使用不强制激活的显示方式，避免用户刚切换窗口就被抢回焦点。用户主动关闭或已开启新会话时不复活旧面板，相关旧动作只取消。隐藏与结果通知由 AHK 动作结果驱动，不由网页先隐藏后等待后端。

发送按键前再次核对前台窗口及剪贴板序号。若用户已产生更新的剪贴板内容，则取消本次自动发送、保留新内容并恢复面板反馈；不降级为又一次覆盖用户新内容的复制。`SendInput` 使用现有不会回入 Ctrl+V 拦截的路径。前台检查与按键送出不能形成跨进程原子事务，首版不承诺操作系统在两者之间绝不切换焦点。

“已发送粘贴”只代表已向正确前台窗口发送按键，不承诺目标应用已经接收图片/文件或完成复制。权限不匹配、目标应用不支持某种格式等行为在错误提示或使用说明中说明，不自动提权。

### 5.3 右键菜单、收藏和删除

| 菜单按钮 | 行为 |
| --- | --- |
| 查看 | 文本在小窗显示完整原文，图片在小窗显示原图并支持缩放、拖动；文件使用系统默认应用打开，多文件先选择一项 |
| 复制 | 与单击一致，写入完整内容，面板保持打开 |
| 粘贴 | 与双击一致，使用本次会话的外部目标 |
| 收藏 / 取消收藏 | 修改收藏标记和收藏时间，更新星标与总数；不写剪贴板 |
| 删除 | 删除指定历史及其数据库内载荷、缩略图；不删除源文件，不改变当前系统剪贴板 |

右键仅选中目标项并打开菜单，不触发单击复制。菜单固定绑定该 ID，使用共享图标、颜色与控件状态，越界时调整位置；点击外部或 Esc 关闭，支持菜单键/Shift+F10 和键盘导航。

查看复用 `AppDialog.open` 和共享主题。文本小窗按需读取完整 `text_plain`，保留换行、空格和缩进，通过滚动浏览全文，不使用列表的 240 字符预览或行数上限。图片按需从可重放快照读取原始 PNG，或把 DIB 按原始分辨率转换为 PNG；不使用列表缩略图。图片小窗支持滚轮/加减按钮缩放、拖动移动、适应窗口和 100% 原始大小，关闭时释放图片 URL 和事件监听。

查看小窗以 `initialFocus: false` 关闭共享弹窗的延后聚焦，在异步内容到达后聚焦完整文本、文件选择列表或图片画布，避免首帧回调覆盖操作目标。共享弹窗的聚焦回调同时绑定本次弹窗的打开状态，关闭或替换后不再执行。

完整查看内容通过 WebView2 只读共享缓冲区传递，页面接收后及时释放缓冲区，不写临时内容文件、不更新复制时间、不写系统剪贴板。请求及响应绑定会话、查看请求和记录 ID；关闭小窗或重开面板后丢弃过期响应。文件打开请求仅传记录 ID 和选择序号，宿主从保存的 CF_HDROP 读取并核对路径后调用系统默认应用；源文件已移动或删除时给出明确提示。

普通记录删除立即执行；删除收藏记录复用确认框，提示“删除后会同时移除收藏”。操作完成前禁用重复提交。删除后选择相邻可见项，保留当前筛选和搜索。

收藏持久化，重启后保留；收藏不是额外复制一条记录。同内容再次捕获时保留收藏标记。收藏不自动置顶，所有列表保持最近捕获在前；收藏筛选中按同一规则排序。收藏项免于自动容量淘汰和底部“清空”，用户仍可通过该项右键“删除”并确认来单独删除。

### 5.4 底部清空

按钮文案为“清空”，全库没有未收藏记录时禁用；只有收藏项时仍显示这些记录，并提示“没有可清空的历史，收藏会保留”。执行范围是整个历史库中的未收藏记录，包括文本、图片、文件和富文本，不受当前搜索/类型/收藏筛选影响。即使正在查看收藏列表，清空仍只作用于全库的未收藏项。

复用 `AppDialog.confirm()`，建议确认文案：

> 清空未收藏的剪贴板历史？
>
> 将清空全部未收藏历史，当前共 N 条；M 条收藏会保留。确认期间新增的未收藏记录也会一并清空，无法撤销。不会删除原文件，也不会清空当前系统剪贴板。

按钮为“取消”和危险样式“清空未收藏”。取消、Esc、关闭对话框均不提交清空。

确认后以单次数据库事务删除 `is_favorite = 0` 的记录及其关联载荷和缩略图，保留收藏记录、收藏标记、载荷、缩略图和原有 ID。页面在提交成功后重新查询当前条件：仍匹配的收藏继续显示，没有匹配项才显示空状态。失败回滚并保留原列表，不能先清空 UI 再报告失败。不删除数据库文件、不删除任何源文件或项目文件。

是否保留以清空事务执行时的收藏状态为准；确认框期间新增的未收藏历史包含在清空范围内。后端清空动作增加捕获代次，取消旧代次会重建被清空非收藏记录的待入库任务和旧页面操作，防止旧队列重新写回。清空后新复制仍正常记录；仅因系统剪贴板还保留上一项而收到的旧通知不补录。

清空事务与入库任务互斥，在极短的协调边界冻结旧队列。提交成功后丢弃会重新生成未收藏记录的旧任务并应用新代次；只更新既有收藏内容的任务可重新校验、归入新代次，但不得新增未收藏记录。事务失败恢复原队列和捕获状态，不因为一次失败的清空丢失待保存内容。新的用户复制按动作实际发生边界划分，不按定时器启动时间划分。

列表和计数缓存失效重查，被删除条目的载荷与缩略图缓存同步释放，收藏内容保持可用。数据库的逻辑清空不等同于对磁盘残留数据作取证级擦除；不在本功能中承诺安全擦除。

### 5.5 多选

底栏“多选”进入多选状态并变为“取消多选”。多选状态下单击列表项只切换选中，不复制；双击不触发粘贴。分页时保留选择，搜索或筛选条件改变时清空选择。底栏显示已选数量，并提供“添加备注”和“删除”；备注将同一段非空文本写入所有选中项并覆盖其原备注，删除则始终确认，且可删除收藏或置顶记录。

## 6. 自动记录和现有多剪贴板的协作

### 6.1 记录入口

继续使用现有 `OnClipboardChange(HandleClipboardChange)`。删除“历史判定在早返回之前完成”的模糊约定，改为公共回调最前端调用 `ClipboardHistoryNotify(dataType, reason, sequence)`：它只登记事件、事务上下文和序号，不枚举/读取正文格式、不采集数据、不决定复制成功。

公共回调的处理顺序固定为：

1. 读取当前序号与公共挂起管理器提供的 reason/操作 token，调用 `ClipboardHistoryNotify()` 取得事件凭据；自身已登记写入、基线及重复序号仅更新状态，未知来源不直接采集。
2. 系统槽位分支独立判断 `AllowClipboardWatcher`、`CapsLockHeld`、`ClipboardSuspendDepth` 和自身写入来源，保留槽位开关的早返回。`allowClipboard=0` 时不执行该分支的 `ClipboardAll()`。
3. 槽位确需更新时，保存读取前序号，取得一次全量快照，再核对读取后序号。两者与事件序号一致才更新系统槽位，并调用 `ClipboardHistoryOfferSlotSnapshot()` 向同一事件提供该对象引用；不在回调中逐块复制或解析大内容。
4. 无论槽位分支正常完成、被开关跳过或失败，都在 finally 中调用 `ClipboardHistoryFinalizeNotify()`。这个步骤只结束登记、允许相应事件进入延迟处理；`Notify()` 不提前启动会与正在进行的槽位快照争用的采集任务。
5. 延迟历史处理先按 reason、成功状态与序号决定是否应记录，再按 §6.2 优先使用已提供快照；没有可用快照才按白名单读取当前同序号内容。

这里“回调前端登记”与“槽位分支读取”是两个边界。整个公共回调仍可能因既有槽位快照等待；历史增加的通知和快照提供步骤不再读取一次剪贴板。关闭独立槽位后历史仍可运行，但只承担自身白名单采集的开销，不承担已被跳过的槽位全量快照。

`dataType` 仅用于快速判空，不能用它确定实际类型：AHK 的 `1` 包含资源管理器复制的文件，`2` 可为图片。捕获时枚举/检查实际格式，主类型优先级为文件 → 图片 → 富文本 → 文本，同一次复制只形成一条记录。

自动记录范围：

- 普通 Ctrl+C/Ctrl+X、应用菜单“复制”和截图工具等外部剪贴板更新。
- CapsLock+C/X 与 CapsLock+LAlt+C/X 的真实复制/剪切成功结果：这些路径当前挂起监听，需要在成功保存槽位处显式提交捕获。
- 项目内用户明确的“复制”动作，例如笔记复制、Everything 文件/路径复制、AI 页复制按钮等；在各实际成功边界接入，避免挂起监听导致漏记。
- 启动和重新开启记录时只建立当前剪贴板序号基线，不读取、不补录现存内容；只记录基线建立后发生的真实新复制/剪切。

不记录选区读取、Tab 热串替换的临时复制、槽位恢复、历史恢复及其再次发送粘贴产生的内部变化；清空系统剪贴板不生成空历史。没有任何可重放的支持格式时不生成占位记录。

程序未运行期间没有记录能力，也不读取或导入 Windows Win+V 的历史。

基线规则同时应用于注册监听后的首次通知和重新开启后的延迟通知：如果当前序号与基线相同，直接跳过。清空/删除会使旧任务失效并保留当前序号的处理状态；重启后再次建立基线，因此留在系统剪贴板中的已删除内容不会自动回来。用户之后主动复制相同内容产生新序号时，仍可重新记录。

### 6.2 延迟通知和序号

AHK 官方说明：自身写入的回调可能延迟，单个布尔值既不能覆盖延迟通知，也无法可靠表达嵌套。当前 `core.ahk` 存在 finally 直接设 false 的路径，而笔记、热串和 Everything 使用恢复 previous 状态的路径；先统一这些入口，再接入自动历史。

#### 6.2.1 统一挂起计数和 reason

以公共 `ClipboardSuspendDepth` 和活动 token 栈作为挂起状态来源，放在公共剪贴板服务中。仓库内部不再直接给 `ClipboardWatcherSuspended` 赋值，也不再各自保存 previous 布尔值；若需要保留兼容读取，该名称只能作为由管理器更新的状态镜像。

| 公共接口 | 规则 |
| --- | --- |
| `ClipboardSuspendBegin(reason)` | 生成独立 token，压入操作上下文，计数加一；reason 是明确的操作种类 |
| `ClipboardSuspendEnd(token)` | 在 finally 中释放自己的 token 一次，只减对应计数；不强制归零，不清除仍活动的外层 reason |
| `ClipboardWrite...(token, data)` / `ClipboardMarkWritten(token, actualSequence)` | 所有真正写入、清空、恢复都经受控入口登记实际序号；失败但已改变剪贴板的部分写入也须登记为不发布历史 |
| `ClipboardCompleteUserCopy(token, sequence, snapshot?)` | 只在明确用户复制/剪切真正成功时发布对应结果；已有槽位快照可以提供给同一历史事件 |
| `ClipboardCurrentContext(sequence)` | 优先查已有的实际写入序号，再读取活动操作上下文；无依据的变化保留为未知来源，不猜成用户复制 |

不变量为 `ClipboardSuspendDepth = 尚未结束的活动 token 数`，且始终非负。重复/不匹配的 End 作为协调错误报告，不靠赋 false 或清空栈“修复”。作用域覆盖一次同步操作，不能跨定时器重试、页面消息返回或无期限等待持有 token；每次实际写入尝试重新进入/退出作用域。

reason 至少包括 `user-copy`、`user-cut`、`temporary-selection`、`temporary-paste`、`temporary-hotstring`、`slot-restore`、`history-replay` 和 `restore-previous`。顶层用户动作负责发布许可，复用的底层文本/图片写入器继承调用者的操作 ID 和记录策略：例如“粘贴笔记图片”调用图片写入器时仍是临时粘贴，不能因为调用了名为 SetClipboard 的函数就新增历史。

reason 是本程序显式操作上下文，Windows 通知本身没有提供这项信息。挂起期间无法确认来源的序号先登记、暂不采集；作用域结束后，仅对仍是当前内容、且没有被实际写入/恢复序号排除的候选再评估。不得把 End 时读到的当前序号一概标成内部写入，以免把期间用户的新复制吞掉。受控 native 写入在剪贴板锁定期间取得本次实际序号，合成 Ctrl+C/X 则由成功边界提交实际 copySequence；普通快照读取本身不是写入，不能为它虚构写入序号。

迁移检查必须覆盖现有全部入口，再启用历史服务：

| 入口 | reason 和处理责任 |
| --- | --- |
| `GetSelectedText()` | 临时选区；合成复制及 finally 的旧内容恢复均归同一事务，恢复使用单独标记 |
| `CopyToClipboardSlot()` / `SaveClipboardSlot()` / `clipSaver()` | 复制/剪切动作持有 user token；Save/clipSaver 本身只读快照，提供同序号引用，不重复发布 |
| `PasteClipboardSlot()` / `PasteSystemClipboard()` / `RestoreClipboard()` | 槽位/旧值恢复；调用方明确原因，结束内层作用域不能解除外层挂起 |
| `SetClipboardText()`、`CLhotString()`、`TabHotStringAction()` | 临时粘贴或热串；清空、替换、恢复各自登记，不能漏掉兼容函数的直接赋值 |
| 笔记文本/图片复制及粘贴入口 | 复制动作成功才发布；粘贴调用底层图片/文本写入器时继承临时原因，包含 finally 恢复 |
| Everything 文本和 CF_HDROP 复制 | 显式用户复制；有限重试的“已排队”不算成功，只有实际 SetClipboardData 成功后发布 |
| 历史复制/粘贴及其失败恢复 | history-replay / restore-previous；不作为新历史发布 |

对 `A_Clipboard :=`、`EmptyClipboard`、`SetClipboardData` 和旧挂起变量写入做静态引用清单，任何遗漏入口都不能以“以后会登记序号”替代迁移。短 `Critical` 只保护 token/登记表更新，不包住读取、等待、SQL 或图像转换。

#### 6.2.2 轻量通知与快照复用

`ClipboardHistoryNotify()` 只产生 `{ eventId, sequence, reason, operationId, suspendDepth, epoch, observedAtUtc, captureOrder }` 等元数据，`observedAtUtc` / 单调 `captureOrder` 在观察事件时分配；由实际写入登记确认的自身恢复/临时内容，以及基线和重复通知，只登记而不排入正文采集。仅落在活动作用域中但来源未确认的序号保持待判定，不能仅凭当前 reason 永久排除；明确用户复制尚未确认成功时则等待成功入口，不能仅因通知到达就发布。

`ClipboardHistoryOfferSlotSnapshot(eventId, sequence, snapshot, formatContext)` 在公共回调和显式复制入口使用同一规则：只接收读取前后序号都与事件一致的快照；提供已有对象引用及该次格式/策略上下文，既不再次 `ClipboardAll()`，也不当场解析或复制全部字节。借用对象由事件持有稳定引用，不能通过晚读全局 `SystemClipboard` 获得可能已经换成下一条的快照。

`ClipboardHistoryFinalizeNotify()` 在公共回调退出时安排延迟任务。处理时优先逐块校验提供的快照，核对捕获代次、reason、成功标记和隐私策略，再只复制允许的格式。只有同序号快照已经固定时，后续系统剪贴板发生变化仍可处理这份固定数据；不得据当前剪贴板查询去拼接旧快照缺失的格式或策略。

复用的全量快照引用也会延长其生命周期，按实际 `Size` 为历史借用引用预留占额；共享同一对象不重复分配，但不能在槽位被替换后将旧对象无限留在队列里。完成白名单提取立即释放借用引用。若无法预留占额、快照序号不匹配或缺少必要的原始格式/隐私信息，不借用该快照；仅在当前序号仍对应事件时走独立白名单路径，否则结束旧事件。

| 状态 | 系统槽位分支 | 历史延迟处理 |
| --- | --- | --- |
| 独立槽位开启、无挂起、外部更新 | 读取一次原有全量快照 | 优先复用同事件快照，不重复从系统读取正文 |
| 独立槽位关闭或该通知不更新槽位 | 不取得系统槽位全量快照 | 记录开关允许时，只对白名单采集 |
| CapsLock 槽位复制/剪切成功 | 保存对应槽位快照 | 显式成功入口提供同序号快照，合并同一事件 |
| 临时写入、恢复或 history-replay | 不误作新的外部系统槽位更新 | 仅登记/排除，不采集正文 |
| 历史记录关闭 | 槽位按原开关运行 | 不保留正文引用，不启动采集；Notify 可用于共同序号管理 |

#### 6.2.3 无快照时的白名单路径与限制

延迟采集严格绑定事件序号：打开剪贴板前及打开后再次核对，序号已改变就丢弃旧请求。新的当前序号由新的通知或补充序号检查形成新事件，不能把此时新内容记成旧事件。

采集先检查排除历史的格式标记，然后仅取得 §7 白名单格式。每次取得 HGLOBAL 后先用 `GlobalSize()` 检查长度和本条/当前内存预算，再分配本程序 Buffer；在同一剪贴板读取区间内复制完必要数据，原句柄不留给后台。关闭前后核对序号，来源变化就丢弃混合结果。采集过程不写入系统剪贴板。

`OpenClipboard()` 忙时建议最多三次、间隔 30ms 的定时重试；每次核对来源序号、操作 token、捕获代次、记录开关和删除状态。所有受管缓冲分配先预留额度，不能以入库后释放充当采集限额。

无论有无借用快照，快照解析、SQL、图像解码和面板创建均在通知登记路径之外执行。槽位分支保留原来的全量快照开销，不能据历史 Notify 足够轻量就宣称整个公共回调无阻塞。

AHK 回调运行期间可能丢失后续通知；极快连续复制、采集之前就被覆盖的内容和来源延迟渲染都可能造成漏项。只要求来源一致、不误记、不重放错误项，并尽量记录仍可取得的最新真实内容，不承诺每一次变化必然保存。显式成功入口已经固定的数据则按原事件处理，§13 使用同一边界。

`GetClipboardData()` 可能触发来源延迟渲染，单次 Win32 调用无法被同进程定时器强制中断。首版只承诺有限打开重试、白名单读取和受管缓冲预算，不承诺整段采集有硬超时或整个进程总内存低于该预算。来源分配、系统映射、native 编解码和原有槽位属于另外的开销；若要保证这些情况下主热键进程始终响应，需另行评估隔离采集进程与取消协议。

### 6.3 保持三个槽位语义

历史复制/粘贴属于系统剪贴板动作。成功恢复载荷后，显式更新 `SystemClipboard` 为本次已准备好的、符合公开结构的 `ClipboardAll(buffer)` 对象并设置 `WhichClipboardNow := 0`，即使独立剪贴板监听处于挂起状态。这里不调用无参数 `ClipboardAll()` 再次抓取系统剪贴板。否则下次普通 Ctrl+V 可能恢复旧系统槽位，覆盖刚选择的历史。

历史操作不改 `CapsClipboard` / `CapsAltClipboard`。独立槽位的复制结果汇入历史，不把历史当作新槽位，也不更改现有 CapsLock+V 和 CapsLock+LAlt+V 的来源选择。

同步系统槽位时仍需核对本次写入的序号；若期间发生新的外部复制，以新内容为准，不把历史快照再写回或更新成过期槽位状态。

记录开关与 `[Global] allowClipboard` 独立：关闭独立槽位仍可记录历史；关闭历史仍可使用现有槽位和已保存历史。

## 7. 内容格式、持久化和恢复

### 7.1 支持范围

| 内容 | 首版需要支持的格式 | 恢复策略与边界 |
| --- | --- | --- |
| 纯文本 | CF_UNICODETEXT；仅在确实缺少 Unicode 时读取 CF_TEXT/CF_OEMTEXT/CF_LOCALE 并用 Windows 编码转换补充 Unicode | 保存一个完整 Unicode 正文；不截断、不对内部空白、大小写或换行做去重归一化 |
| 图片 | 注册格式 PNG、CF_DIBV5、CF_DIB，按该顺序择一 | 持久化一种完整图片载荷；兼容后备在恢复时生成，列表缩略图独立保存 |
| 文件/文件夹 | CF_HDROP，多路径 | 构建真实文件剪贴板，不用文本路径替代；重放统一为复制 |
| 富文本 | `HTML Format`、`Rich Text Format`，并保留可用纯文本 | 恢复格式化载荷和后备文本，目标应用自行选择支持格式 |

系统可将 CF_BITMAP 合成为 DIB/DIBV5，优先取得这些可持久化数据。确需位图转换时使用 Windows/GDI+ 接口，不把 HBITMAP 数值当作图片正文保存。透明度、尺寸、颜色及完整图片数据属于后续实际验收项目。

图片选择规则：存在有效且合规的 PNG 时只保存原始 PNG；否则尝试 CF_DIBV5，再尝试 CF_DIB，只保存首个完整且合规的候选。候选损坏或超限先释放对应临时 Buffer，再尝试下一种；所有候选都失败时跳过整条，不用缩略图或截断数据代替原图。附带文字只作有界搜索说明，不同时保留第二份像素载荷或无关 HTML。来自文字片段的 HTML/RTF 与纯文本继续按富文本规则组合保存。

复制图片时恢复原始图片格式；保存 PNG 的记录在像素预算允许时，使用 Windows/GDI+ 图像能力生成一个 DIBV5（或适用的 DIB）兼容后备。该后备不持久化、不进入去重身份，释放规则和内存预算与复制动作一致。超过解码预算或生成失败时仅复制可用原格式，并提示“部分应用可能不支持该图片格式”；不能宣称所有目标应用均可粘贴。

首版不承诺应用私有对象、任意 COM 指针、OLE 嵌入对象、元文件或 Outlook 等虚拟附件的全保真重放。只有 `FileGroupDescriptor` / `FileContents` 而无真实 CF_HDROP 的项目不能标成已支持文件；存在文本后备时仅按该后备记录并标明格式降级。

HTML/RTF 存的是格式化文本字节。HTML 中引用外部图片、临时文件或网页资源时不自动下载或备份；再次粘贴的完整外部资源能否显示取决于资源和目标应用。

### 7.2 快照和注册格式名

历史按 §6.2 优先使用同事件借用快照，逐块检查结构并只提取 §7.1 白名单格式；源快照已有的未知数据不再复制到历史。公共回调提供的 `formatContext` 至少记录该次序号下的格式 ID/注册名和策略标记可用性；标记值从对应快照解析，原来存在但快照缺少的策略信息不能按“允许记录”默默补全。

无可用借用快照时，历史才使用 Windows 官方剪贴板 API。`EnumClipboardFormats()`、`IsClipboardFormatAvailable()` 和 `GetClipboardFormatNameW()` 用于识别，不对未知/私有/OLE 格式调用 `GetClipboardData()`。排除历史的策略格式只读取必要的小标记，不作为正文持久化。这些识别/读取属于延迟采集或既有槽位阶段，不放进 `ClipboardHistoryNotify()`。

独立采集取得白名单句柄后校验 `GlobalSize()`、长度上限和预计内存占额；锁定、复制、解锁均在 `CloseClipboard()` 前完成。借用快照路径则以已校验块长度作同样预算检查，不再读取系统句柄。两条路径均对 CF_HDROP 校验 DROPFILES 头、编码和双零结尾，对文字校验终止符，对 PNG/DIB 校验头部、宽高、偏移和长度的算术溢出，再由 native 编解码器生成派生预览。读取失败只处理允许格式的候选后备；不为历史回退到额外一次全量 `ClipboardAll()`。

从已拥有的、完整校验过的 Buffer 块构建 `ClipboardAll` 公开二进制结构：每组“4 字节格式编号 + 4 字节长度 + 内容”，末尾为 4 字节零编号。总大小先计算并预留预算，再分配；不能边追加边无限扩容。持久化对象只含选定的可重放格式及其名称映射。

读取数据库中的快照或利用现有槽位快照时同样校验所有偏移、长度、终止标记和总大小，不能把损坏数据交给 `NumGet` 或恢复接口。未知的指针/句柄格式不复制、不持久化、不擅自重放。已有槽位持有快照的内存属于原有功能；历史延长其生命周期时，将借用引用的整份 Size 计入自己的占额，并在提取后释放。这个占额限制历史保留旧对象的数量，不能据此声称原有槽位本身的内存也受到历史限额保护。

注册格式 ID 在 Windows 运行会话中分配，不能只存旧编号。对允许的注册格式保存 `{ originalId, name }`，加载恢复时通过 `RegisterClipboardFormatW(name)` 获得当前编号，再重建快照头；标准格式使用固定编号。格式名称用 `GetClipboardFormatNameW()` 查询。这样图片 PNG、HTML、RTF 能跨程序重启和 Windows 重启恢复。

保持有信息量的格式在前，保留富文本中所选支持格式的顺序；不把富文本强制降级为纯文本。只有一种图片格式是有意的保存策略，恢复时可生成后备。必需格式缺失时只记录实际可重放内容，并标记降级或失败，不宣称保存了全部来源格式。

### 7.3 文件路径与剪切标志

文件历史保存路径列表和必要的 CF_HDROP，不复制文件本体、不遍历目录。源文件移动、改名或删除后，旧历史不会自动找到新位置。

文件恢复使用路径重新构建 Unicode DROPFILES。剪贴板 owner 使用项目有效 HWND，不照搬现有 `OpenClipboard(0)` 的参数：Windows 文档指出其后 `EmptyClipboard()` 可能让 owner 为空并使 `SetClipboardData()` 失败。

不重放来源的 `Preferred DropEffect=move`、`Performed DropEffect`、`Paste Succeeded` 等传输协商格式；根据需要明确设置复制效果 `DROPEFFECT_COPY`。历史文件操作不会再次剪切、移动或删除源文件。

首版不在捕获、列表渲染、复制或粘贴前主动检查源路径存在性、读取源文件、计算源文件大小或遍历目录。本地路径、UNC、`\\?\UNC\` 和映射盘均只按已保存的路径字符串处理，避免把本地盘符或重解析路径误判成不会访问网络的路径。校验只针对路径列表的结构和长度；恢复完整路径组，不悄悄过滤其中任何项目。

文件可用性、访问权限和真正的数据传输由资源管理器或其他目标应用处理。源路径失效时，复制动作仍能成功恢复这组路径，目标应用可能在粘贴时拒绝、提示或只处理部分项目；历史面板不能据发送一次 Ctrl+V 宣称整组文件已经传输成功。记录原路径不随目标应用的结果自动删除或改写。

文件列表图标采用通用文件/文件夹图标，或以扩展名配合 `SHGFI_USEFILEATTRIBUTES` 取得类型图标；不调用会打开真实源路径的 Shell 图标提取或缩略图接口。本期不提供“失效数量”预检结果，也不以 AHK 定时器声称可以中断一次同步网络文件调用。

所有格式缓冲区与全局内存在清空系统剪贴板前准备好；通过 `SetClipboardData()` 成功移交的内存由系统负责，未移交的内存由本程序释放，`CloseClipboard()` 放入 finally。多格式写入失败明确反馈，不把部分成功当作全部成功；确需恢复旧剪贴板时只在序号仍属于本操作时执行。

## 8. 数据库与容量

### 8.1 存储位置与结构

建议固定位置：`{app}\data\clipboard-history\clipboard-history.db`，由 AHK 使用 `A_ScriptDir` 构建完整路径。按当前安装器默认目录，它对应 `%LocalAppData%\capslock_p2\data\clipboard-history\clipboard-history.db`。复用当前 SQLite DLL，数据库内保存快照和 PNG 缩略图，不额外生成持久化图片文件或媒体目录。

这个数据库是安装目录中的运行数据：安装包不携带数据库/用户历史，升级不覆盖它，卸载不删除它。将程序迁移到另一个安装目录时，用户需连同 `data\clipboard-history` 一起迁移。路径遵循新增的 `AGENTS.md` 大型存储约束；按打包说明，安装目录必须可写。本期不设计静默回退到 `%AppData%`，以免一次复制历史后出现两份彼此分叉的数据库。

建议结构：

| 表/字段 | 用途 |
| --- | --- |
| `history_meta`：schema_version、格式版本等 | 使用真实版本检查和事务迁移，拒绝打开更高版本执行写入 |
| `clipboard_items.id` | 不复用的稳定 UUID；页面收到字符串，避免 JS 整数精度问题 |
| `primary_type`、`is_rich_text` | 类型筛选和富文本标记 |
| `content_hash` | 按类型与可重放内容精确去重，不使用序号或时间作为内容身份 |
| `text_plain`、`search_text`、`preview_text` | 正文/可读搜索材料/有界预览，完整正文不发给列表页面 |
| `file_count`、`image_width`、`image_height`、`byte_size` | 列表所需的轻量计数/尺寸/容量信息；完整文件路径保留在可重放快照和搜索文本中 |
| `last_captured_at_utc` | 最近捕获或成功复制时间，统一用于列表排序、日期筛选和过期清理，精确到毫秒 |
| `is_favorite`、`note_text`、`is_pinned`、`pin_order` | 收藏、备注和多项置顶；置顶次序由 `pin_order` 决定 |
| `clipboard_payloads.item_id`、`snapshot_blob`、`format_manifest_json`、`payload_version` | 一对一完整快照及其格式清单，避免在元数据表重复保存清单；外键级联删除 |
| `clipboard_thumbnails.item_id`、`png_blob`、`width`、`height` | 一对一派生缩略图，失败不影响原图重放 |

索引包括 `content_hash` 唯一索引，以及按置顶状态、置顶次序、最近时间和 ID 排序的列表索引。最近时间采用毫秒精度；复制历史项只更新时间，不维护额外采集/排序序号。列表查询只取有界预览和 `file_count`，不把每项完整路径数组或快照 BLOB 载入 WebView2。

`byte_size` 计算本条已保存快照字节、正文/搜索/路径/预览等元数据的 UTF-8 字节和缩略图实际字节之和，避免重复存储的文本或派生数据逃过有效数据预算。SQLite 页、索引和日志文件的额外空间不混同于这个逻辑计数。

现有 `CSQLite.GetTable()` 经 `sqlite3_exec` 的字符串回调读取，不能用它读取 BLOB。历史存储模块通过库已打开连接的 `ptr` 调用 SQLite 官方 `sqlite3_prepare_v2`、`sqlite3_bind_text16` / `sqlite3_bind_blob`、`sqlite3_step`、`sqlite3_column_blob` / `sqlite3_column_bytes`、`sqlite3_finalize`，小范围封装参数与资源释放，不修改 vendor 库。

BLOB 写入使用复制语义的绑定生命周期；读取结果在 step/finalize 前复制进独立 Buffer。二进制不转 SQL 字符串、不用巨大十六进制拼接、不通过 COM 字节包装进行数值运算。

缩略图由 AHK 从已捕获快照生成，生成失败显示图片占位图，继续保留可重放的原图。页面只为已加载、可见的图片请求有界 PNG 数据，优先以小 data URI 传送；不创建本地全盘映射、不暴露真实文件路径作可导航媒体 URL。

### 8.2 去重

- 文本按完整内容比较；同文字的纯文本与带 HTML/RTF 的富文本不能合并丢格式。
- 富文本按纯文本和允许的格式化载荷组合去重，注册格式以名称比较。
- 图片按所保留的重放内容去重；不同编码但视觉相同不强行合并，不额外做图像相似检索。
- 文件按有序完整路径列表去重；同一文件列表的复制和剪切合并为复制语义。
- 哈希使用现有 BCrypt/SHA-256 能力，编码包含类型、格式键和数据长度，排除动态序号、收藏、时间和缩略图。重复哈希候选必要时比对实际内容。
- 真实外部再次复制同内容：更新最近捕获时间/序号，保留 ID、首次时间和收藏。
- 历史里的复制/粘贴、单纯重启加载：不修改捕获顺序，不产生新记录。

### 8.3 容量参数（暂定）

自动记录和完整图片可能持续消耗空间，建议初始参数如下，实施时通过配置元数据统一校验：

| 参数 | 建议默认值 | 规则 |
| --- | --- | --- |
| 记录开关 | 开启 | 可以关闭自动记录，已有历史仍可查看和使用 |
| 非收藏最大数量 | 500 条 | 收藏免于自动条数淘汰 |
| 单条图片原始载荷上限 | 128 MiB | 只保存一种 PNG/DIBV5/DIB，按实际原始载荷字节计算，不压缩到缩略图来规避限额 |
| 单条文本/富文本/文件载荷及元数据上限 | 32 MiB | 按选定支持格式与元数据的合计字节计算，超限不截断为可用记录 |
| 有效载荷/缩略图合计预算 | 512 MiB | 优先淘汰最旧非收藏；收藏占满时跳过新内容并提示 |
| 待处理事件保留的剪贴板快照预算 | 256 MiB | 限制历史事件额外持有的全量快照引用；超预算时不保留引用，并在剪贴板序号仍匹配时回退到受单次采集上限约束的格式读取 |
| 单张缩略图上限 | 128 KiB | 限制仅用于列表的 PNG；缩略图失败/超限不丢原图 |
| 图片解码像素预算 | 约 4000 万像素 | 限制缩略图解码开销；超限可保留合规原始快照并显示占位图 |
| 图像转换预计展开上限 | 192 MiB | 在创建图像前校验宽高、stride、位深和预计字节；超限不解码，保留合规原载荷 |

4K（3840 × 2160）的 32 位像素数据约 31.6 MiB，8K（7680 × 4320）约 126.6 MiB；单份常见 32 位 DIB 连同标准头部可落入 128 MiB 图片上限。PNG 使用编码后的原始字节计数，DIB 使用包含头部/色表/像素的块大小计数；不把多个重复图片格式累加后再误判成一张图超限。异常大图、过大色彩配置或其他超限载荷仍明确跳过。

图片附带搜索说明建议至多 4 KiB UTF-8，不持久化无关的大文本/HTML；快照结构和格式映射有独立的有界开销，并计入 512 MiB 有效数据预算。文本/富文本的正文与格式化数据仍完整保存，不采用图片说明的截断规则。

256 MiB 预算约束历史事件额外保留的全量快照引用；捕获/解析/哈希/入库流水线串行执行，单次捕获上限为 256 MiB，且 SQLite 绑定在源 Buffer 保持有效期间使用静态引用，避免再复制一份 BLOB。该预算不是进程总内存硬上限：既有剪贴板槽位、当前捕获所需的格式块与归档副本、SQLite 页缓存和 native 解码库的分配不包含在内。全量快照已由现有槽位路径创建后才交给历史服务，因此预算控制的是历史队列持有时间，不声称能阻止该既有分配本身。

native 图片解码工作空间还受像素/stride/位深和预计展开字节检查约束；先校验头部，再创建图像对象。图片解码单独串行，只生成列表需要的小预览或当前复制动作需要的兼容后备，不为所有记录预先解码。该原始缓冲预算不声称覆盖原有槽位、SQLite 页缓存、WebView2、系统共享数据或 native 库内部的全部分配。

容量预算是数据库有效数据预算，不代表文件在 SQLite 内部页复用下总能自动缩到该物理大小。删除后空间由数据库后续复用，首版不在复制回调或操作完成时自动执行昂贵的 VACUUM。

大对象采集按 §6.2 和 §7.2 在本程序复制每个白名单格式前检查实际长度。来源延迟渲染、`GlobalSize()` 前的系统数据准备和一次 native 解码不能靠定时器中止；这些调用的时延是首版明确保留的兼容性边界，不以“后台任务”名义承诺硬超时。

新增记录、更新去重项、容量淘汰和关联数据保存作为事务执行。数据库忙则有界重试已捕获任务；失败后不影响用户原复制操作。持久化失败通过面板状态/合并反馈报告，日志只记录类别、长度、计数与错误码。

后台服务建议公开以下职责接口；具体命名以实施时统一为准：

| 接口 | 职责 |
| --- | --- |
| `ClipboardHistoryInitialize()` / `Shutdown()` | 加载 Qbar 剪贴板工具的插件设置、打开存储、只建立序号基线不补录；退出时停止任务并关闭存储 |
| `ClipboardHistoryNotify(dataType, reason, sequence)` | 回调前端只登记；返回事件凭据，不读取格式正文、不直接判定复制成功 |
| `ClipboardHistoryOfferSlotSnapshot(eventId, sequence, snapshot, formatContext)` | 公共回调或显式成功入口提供同序号快照引用，有限占额，不复制/解析正文 |
| `ClipboardHistoryFinalizeNotify(eventId)` | 回调 finally 结束登记、决定是否排队，保证先有机会提供槽位快照 |
| `ClipboardHistoryRequestCapture(event, preCaptured := 0)` | 显式用户复制与通知的统一入口，固定事件元数据；可接收同序号的既有快照作白名单数据来源 |
| `ClipboardHistoryCaptureAllowedFormats(event)` | 优先校验/提取同事件快照，否则核对当前序号后独立读取白名单，形成自有 Buffer |
| `ClipboardHistoryProcessPending(*)` | 对已经固定的快照去重、生成缩略图、事务入库、通知可见面板 |
| `ClipboardHistoryList(query)` | 带筛选/收藏/游标的分页读取，不取正文 BLOB |
| `ClipboardHistoryCopy(id, sessionId)` / `Paste(...)` | 验证当前记录和会话，恢复载荷并同步系统槽位 |
| `ClipboardHistorySetFavorite(id, desiredState)` | 设置确定状态，避免重复消息把收藏反复翻转 |
| `ClipboardHistoryDelete(id)` / `Clear(confirmToken)` | 单条删除 / 清空未收藏记录，取消相关待处理/页面动作并刷新状态 |
| `ClipboardHistoryShow(search, targetContext)` / `Hide()` | 接收已经冻结的可信窗口上下文，延迟创建面板、管理会话和失败恢复 |

队列分成两类：采集请求带固定事件元数据和可选的有界借用快照引用；没有固定快照时，读取前必须核对当前剪贴板仍是该序号，有快照时只读取该对象并校验它与事件的关联。持久化任务必须已经拥有“白名单快照 + 序号 + 捕获代次 + 观察时间/排序号”，不再依赖原槽位对象。每个任务使用 `Bind()` 传值，不能晚读全局槽位或把当前新 `A_Clipboard` 冒充旧事件。

每批后台任务限制处理工作量和字节数，采集、入库、图像转换各自串行协调。关闭记录时取消尚未读取的采集请求；重新开启建立新基线和采集代次，不处理关闭期间的旧请求。已拥有数据的持久化任务按原记录代次完成，仍须服从删除/清空的失效规则。

AHK 计时器共享同一进程执行环境，大图片转换和 SQL 都需要在可分批边界让出事件处理机会；一次 Win32/native 调用内部没有可让出的边界，不把一次定时器延迟称为真正的多线程任务或可强制取消任务。

普通删除需要使已识别为同一条目的旧待处理任务失效，避免点击删除后同一旧捕获又更新/插入。删除提交后的新用户复制同内容可以正常生成新 ID。

退出时先关闭捕获入口、停止重试和预览队列，再释放快照与图像资源并关闭数据库；不在 OnExit 开新面板或无限等待。尚未提交的队列在异常退出时可能丢失，已提交记录以 SQLite 事务为准。

复用图像接口时检查 GDI+ 共享生命周期：历史图像任务全部停止后才能关闭其使用的 token，不能因 QBar 先行退出而使后台缩略图操作使用已释放资源。

## 10. 页面消息与并发约束

所有页面动作只携带 ID、查询条件与明确参数；正文、注册格式、快照和任意文件路径不从页面回传执行。

| 方向 | 消息 | 必要字段/含义 |
| --- | --- | --- |
| 页面 → AHK | `queryHistory` | sessionId、queryId、search、type、favoriteOnly、cursor |
| 页面 → AHK | `copyHistory` / `pasteHistory` | sessionId、requestId、itemId |
| 页面 → AHK | `setFavorite` | sessionId、requestId、itemId、desiredState |
| 页面 → AHK | `deleteHistory` | sessionId、requestId、itemId |
| 页面 → AHK | `prepareClear` | sessionId、requestId；取得待清空的未收藏数量、保留的收藏数量和一次性确认 token |
| 页面 → AHK | `clearHistory` | sessionId、requestId、confirmToken；只在确认框确认后发送，后端固定仅清空未收藏项 |
| 页面 → AHK | `cancelClear` | sessionId、confirmToken；取消确认时主动使 token 失效 |
| 页面 → AHK | `requestThumbnail` | sessionId、queryId、itemId；只能请求当前授权列表项 |
| AHK → 页面 | `historyResults` | sessionId、queryId、storeGeneration、rows、counts、nextCursor |
| AHK → 页面 | `clearInfo` | confirmToken、nonFavoriteCount、favoriteCount |
| AHK → 页面 | `actionResult` | requestId、action、ok、errorCode、用户可读信息 |
| AHK → 页面 | `historyChanged` / `thumbnailResult` | 版本变化通知 / 指定条目有界缩略图 |

`sessionId` 在每次打开时更新；隐藏/关闭后旧会话消息不再可执行。复制/粘贴以稳定 ID 再读当前数据，绝不用数组下标。`requestId` 防止重复粘贴和重复清空；每个动作任务收到消息后及延迟执行前均校验。

已校验的粘贴动作仅在激活确认后由自身流程隐藏面板，此时可以继续完成同一动作；主动隐藏不等同于收到用户关闭。失败恢复遵循 §5.2 的可见性边界，只有当前会话且未被用户关闭的动作可恢复面板。用户关闭、再次唤起产生新会话或新动作取消它时，未完成的激活/写入/重试必须失效，不借失败反馈重开旧窗口。

清空 token 只对当前面板会话一次有效，取消或关闭后失效；后端消费 token 后才执行事务。token 用于确认流程和旧消息失效，不宣称能对不可信网页提供安全认证。

列表翻页使用固定查询/数据代次的游标；新增/删除/去重改变排序时旧分页响应失效。用户在列表顶部时可以合并新记录；滚动浏览中保留稳定锚点，不突然跳到顶部或更换当前行。鼠标双击窗口期间延迟结构性列表刷新，操作结束再应用。

收藏筛选下取消收藏会移除该行；删除/清空刷新计数与空状态，清空完成后继续展示当前筛选下的收藏项。收藏动作更新失败时回滚页面标记。确认框开启期间仍可接收变化通知，但不抢走焦点。

WebView2 消息回调只解析、校验与排队，不同步 `await2` 创建面板、不长时间访问剪贴板或数据库。所有 AHK → 页面数据按既有 JSON 序列化方式发送。

## 11. 隐私与内容展示

历史属于本机持久化数据；本期不增加云同步、上传、OCR 服务或第三方依赖。数据库与页面缓存不作为安装包输入。

尊重 Windows 的剪贴板排除信号：存在 `ExcludeClipboardContentFromMonitorProcessing`，或 `CanIncludeInClipboardHistory` 为 DWORD 0 时不记录；`CanUploadToCloudClipboard=0` 仅限制云上传，不等同于禁止本地历史。不能保证所有密码管理器都会设置这些信号，不按正则猜测并删除所谓密码。

文本和文件预览用 `textContent`。富文本优先使用同次采集的 CF_UNICODETEXT 后备显示可读文字，不把原始 HTML/RTF 注入页面、不执行链接、不加载其中的远程资源。没有后备时保留格式化载荷、显示类型占位，不为检索手写 HTML/RTF 解析器。以后若增加格式化预览或文字提取，应使用现有 DOMPurify/不可执行的片段处理或 Windows 原生能力，禁用外部资源加载；派生文字不替代重放原文。

日志继续遵守项目红线：不写正文、快照、文件路径、查询词或 API 凭据；错误使用本地类别与计数，避免直接转储含 SQL 参数或路径的异常信息。首版不宣称数据库已加密，Qbar 剪贴板工具设置和使用说明明确“历史会保存在本机，关闭记录不会自动删除已有历史”。

## 13. 静态验收清单与后续实际确认项目

以下是设计与实现的审阅标准，不是测试代码，也不要求在当前约束下启动应用。

| 场景 | 必须满足的行为 |
| --- | --- |
| 正常速度、来源/格式可取得且未超限的外部复制 | 按实际支持格式形成单条历史；读取失败或内容已被覆盖时如实跳过，不承诺每次变化必然记录 |
| 复制图片和多文件后关闭/重开程序、重启 Windows | 已提交内容可加载；注册格式按名称重绑定 |
| 清空/删除后当前剪贴板仍保留旧内容，再重启或关闭/开启记录 | 只建立序号基线，旧内容不补录；用户之后主动复制同内容仍能形成新记录 |
| 延迟采集前又发生新的复制 | 有同事件固定快照则处理该快照；无快照的旧请求序号不匹配即放弃，不冒用新内容、不写混合格式 |
| CapsLock+Z 唤起 | 打开/隐藏剪贴板历史，个人已有按键覆盖仍被尊重 |
| QBar 输入“剪贴板历史”或 `cv` | 搜索结果命中同一个工具，选中并执行可打开面板 |
| QBar 打开后用户切换外部窗口，再执行历史工具 | 执行入口先读当前前台；只有前台为 QBar 才用同步后的会话目标，旧/不可信缓存不能用于自动粘贴 |
| 普通 Ctrl+V 与独立槽位交替 | 历史恢复后系统槽位状态一致，两个独立槽位不被覆盖 |
| 禁用独立剪贴板 | 历史仍按自己的记录开关运行 |
| 公共回调槽位读取完成，序号与历史事件相同 | 延迟历史优先复用该快照，不重复取全量或读取系统正文；不符序号/预算/策略则走规定的回退 |
| 独立槽位关闭、历史开启 | 跳过槽位 ClipboardAll，只执行历史独立白名单路径 |
| CapsLock+C/X 和 LAlt 层复制 | 明确成功且可用的固定结果只发布一次；不因自己的挂起 token 被误排除，读取/超限失败仍可跳过 |
| 外层临时操作调用内层写入器 | 内层结束后深度/外层 reason 仍有效；finally 和重试分支不直接写 false，不重复释放 token |
| 笔记临时粘贴调用图片/文本复制底层帮助 | 继承临时原因，不误记为明确用户复制；真正复制按钮成功才发布 |
| 翻译读取选区、热串临时替换、槽位恢复 | 临时内容和旧快照不污染历史 |
| 程序写剪贴板后延迟通知 | 自身序号被识别，历史操作不重复新增或置顶 |
| 极快连续复制、回调/采集之前内容已被覆盖 | 允许漏掉不可取得的中间项，尽量记录仍可取得的最新项；不错配来源、不记临时值，不承诺绝不漏项 |
| 单击/双击任意类型行 | 单击复制，双击发起一次粘贴；ID 不随列表刷新改变 |
| 右键行或点击收藏星标 | 不意外触发复制/粘贴 |
| 任意类型 + 搜索 + 收藏 | 筛选共同生效，富文本归文本，计数含义一致 |
| 中文 IME 与旧查询响应 | 组合输入不抢查询，过期结果不覆盖新条件 |
| 收藏后重启、同内容再次复制 | 收藏保留，重复内容合并，时间更新来自真实复制 |
| 文件原本是剪切、后来重放历史 | 重放为复制，不移动/删除源文件 |
| 文件路径部分或全部失效、UNC/映射盘断开 | 面板不查询源文件，完整恢复路径组；目标应用处理失效和权限，不虚报文件传输成功 |
| 双击后目标不存在或激活失败 | 隐藏前就停止，面板保持可见；复制成功才提示已复制，复制失败必须明确反馈，按键不静默丢弃 |
| 激活确认后隐藏，随后写入/发送失败或前台变化 | 取消发送并恢复当前面板可见及原筛选/选中项，反馈失败；用户关闭/新会话则只取消旧动作 |
| 操作期间用户产生新剪贴板内容 | 不恢复旧值覆盖新内容，不误触发自动粘贴 |
| 清空取消 / 确认 | 取消无变化；确认清除全库所有类型的未收藏记录，完整保留收藏，不受筛选限制 |
| 仅剩收藏、或当前正在查看收藏筛选 | 无未收藏项时按钮禁用；存在未收藏项时只清空未收藏项，收藏列表保持可用 |
| 清空时存在旧捕获队列和延迟消息 | 不回填已清空的未收藏内容；收藏及其载荷保持可用，之后新复制正常记录 |
| 单条删除或清空 | 只删数据库记录/载荷，源文件、项目文件、数据库文件不删除 |
| 数据库忙/只读/磁盘满 | 有界反馈、事务回滚，用户原复制动作不被破坏 |
| 大图片、预算用满、收藏占满 | 分配前检查白名单载荷和历史受管缓冲占额；无静默截断、无自动淘汰收藏，不将限额扩大宣称为进程总内存保证 |
| 普通 4K/8K 32 位截图同时携带多种图片格式 | 只持久化一份合规 PNG/DIB；按 128 MiB 原始载荷上限计算，不因重复格式误跳过 |
| 白名单以外存在巨大/私有格式 | 不读取该格式，不先采集全量再过滤 |
| 白名单格式触发来源延迟渲染 | 只有打开重试有上限，单次 native 调用不能用定时器硬取消；用户可见影响不得标成已消除 |
| 图片缩略图失败 | 显示占位并保留可用原图，不能丢失整条记录 |
| 不支持的私有格式或虚拟文件 | 明确降级/不支持，不伪装为完整恢复成功 |
| 深浅色、缩放、菜单/确认框/空状态 | 统一主题和控件状态，不出现独立配色或双主题逻辑 |

本轮可通过阅读、引用搜索、差异审查和 `git diff --check` 审阅文档。AHK 回调时序、系统格式恢复、透明图片、文件粘贴、权限/窗口焦点、IME 和 WebView2 双击行为只能在后续允许的环境中实际确认；当前不标记已实测。

- [Microsoft：GetClipboardData](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getclipboarddata)：只在剪贴板打开期间使用系统句柄，关闭前复制，不能释放来源句柄。
- [Microsoft：GlobalSize](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-globalsize)：查询内存对象大小，在本程序分配和复制前作长度检查。
- [Microsoft：Standard Clipboard Formats](https://learn.microsoft.com/en-us/windows/win32/dataxchg/standard-clipboard-formats)：CF_DIB、CF_DIBV5、CF_HDROP 和纯文本格式。
- [Microsoft：Shell Clipboard Formats](https://learn.microsoft.com/en-us/windows/win32/shell/clipboard)：真实文件路径、虚拟文件、DropEffect 和传输协商格式。
- [Microsoft：OpenClipboard](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-openclipboard)：使用有效窗口作为 clipboard owner。
- [Microsoft：SHGetFileInfoW](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shgetfileinfow)：使用 `SHGFI_USEFILEATTRIBUTES` 时按给定属性获取类型信息，不访问真实文件。
- [SQLite：Binding Values To Prepared Statements](https://www.sqlite.org/c3ref/bind_blob.html)：文本/BLOB 绑定及内存生命周期。
- [SQLite：Result Values From A Query](https://www.sqlite.org/c3ref/column_blob.html)：二进制列、字节长度和结果有效期。
