# capslock_p2 项目审查与结构优化设计

## 目标

在不改变 CapsLock 键层、qbar、翻译、词典、AI 问答主要使用方式的前提下，修复已经确认的行为与隐私问题，统一配置和设置入口，并把大型模块拆成职责清晰、可静态审查的单元。

## 范围

本轮包含以下工作：

1. 修复窗口绑定失效句柄、Everything UTF-8 检测和消息输入校验问题。
2. 调整调试日志，禁止写入 qbar/AI/选区文本和可能包含凭据的 URL。
3. 将配置读取、默认值、校验和写入收敛到独立配置边界，设置变更不再无条件执行全量初始化。
4. 停止数学计算功能：CapsLock+Tab 只处理热串替换；旧数学与脚本运行时文件已按后续用户授权删除，不再被入口包含。
5. 停止 qbar 外观配置：qbar 使用内置主题和固定布局；保留旧 `[QStyle]` 配置文本但不再读取或展示，不主动改写用户文件。
6. 统一设置中心为唯一可视化设置入口；翻译和 AI 面板的设置按钮打开设置中心，不再维护第二套嵌入式设置表单。
7. 将 qbar 按宿主、索引/配置、命令、Everything 和页面样式职责拆分，并抽取 WebView2 面板的公共宿主逻辑。
8. 同步 `README.md`、`docs/architecture.md`、`docs/packaging.md`、使用介绍页和脱敏配置，使说明与实际实现一致。

不在本轮范围内：

- 不修改 `capslock-plus/` 参考目录。
- 不更换 WebView2、SQLite、JSON、Promise 等现有官方/第三方实现。
- 不引入外部运行时、包管理器或新的网络服务。
- 默认不删除仓库文件；本轮用户随后明确授权删除已确认无活动引用的退役源文件和诊断副本，删除范围以整改记录为准。

## 当前问题证据

### 结构问题

- `lib/features/qbar/qbar.ahk` 同时承载窗口生命周期、输入查询、开始菜单索引、文件夹浏览、命令执行、Everything 子进程和 QStyle；文件超过 1500 行。
- `lib/app/core.ahk` 同时承载启动、配置解析/写入、热串、剪贴板、语言、DPI 和启动动画。
- `lib/features/aiChat.ahk` 与 `lib/features/translate/llmTranslate.ahk` 都实现自己的 WebView2 创建、焦点监视、页面执行和关闭流程。
- `pages/settings.html` 有完整的设置中心，`pages/settings.js` 又被翻译/AI 页面作为独立设置弹层使用，导致字段、校验和保存路径重复。

### 已确认的行为问题

- `activateWinAction()` 在单窗口模式下先清理失效句柄，导致后续 `FindReplacementWindow()` 无法执行，记录的程序路径也无法重新启动。
- 同类窗口模式刷新新窗口，但不清理已关闭的窗口句柄，循环列表会积累失效项。
- `QbarIsValidUtf8()` 将普通 ASCII 字节判定为非法 UTF-8，包含中文且以 ASCII 路径开头的 Everything 结果可能回退到错误编码。
- 设置写入统一调用 `ReloadSettings()`；鼠标速度、独立剪贴板等运行时小变更会重复初始化 JavaScript、托盘和所有设置派生状态。
- 设置页窗口绑定的模式名称只暴露实现术语，用户无法直接判断“追加”和“同类”的实际作用。

### 已确认的隐私/维护问题

- qbar 调试日志包含查询文本、执行文本和提交给 AI 的文本。
- LLM 流日志直接写入 endpoint；URL 查询串可能携带凭据。
- QStyle、数学计算、`loadScript` 和旧设置弹层仍出现在代码、页面、示例配置和文档的不同组合中，项目行为和说明已分叉。
- qbar 的 Everything 配置段未进入设置中心，和“可视化配置”的目标不一致。

## 目标架构

### 配置边界

新增配置模块负责：

- 读取 UTF-8 INI 并补入安装模板默认值；不执行旧配置迁移。
- 提供按 section/key 的安全读取和类型校验。
- 以临时文件 + 原子替换写入配置，避免进程在写入中断时留下半个文件。
- 区分“持久化配置变更”和“只更新运行时状态”的操作。

业务模块只能通过配置读取函数取得值，设置中心通过白名单元数据生成字段并保存；私有凭据仍只保存在本机配置，不进入日志和发布资源。

### WebView2 面板边界

新增公共面板宿主模块，统一处理：

- GUI 创建、最小尺寸、Resize/Close/Escape 事件。
- WebView2 loader 路径、用户数据目录、导航完成状态和 controller Fill。
- 页面消息读取、脚本执行、焦点监视和安全关闭。

各面板只保留页面路径、窗口标题、尺寸、消息路由和业务状态；内部函数名可以直接按新边界调整，所有仓内调用点在同一阶段同步更新。

### qbar 边界

qbar 保留 `QbarShow/QbarHide/QbarToggle/QbarExec` 等外部入口，内部拆分为：

- `qbar_panel.ahk`：窗口和页面通信。
- `qbar_index.ahk`：配置条目、开始菜单和过滤排序。
- `qbar_commands.ahk`：内置命令、运行/网址/路径行为。
- `qbar_everything.ahk`：Everything 后端选择、进程调用和 CSV 解码。
- `qbar_navigation.ahk`：文件夹前进/后退和补全。

QStyle 的运行时读取和页面注入被移除；qbar 页面只保留内置设计变量。

### 设置中心

设置中心是唯一可视化配置入口，页面分区为：通用、LLM、翻译、AI 问答、快捷键、Tab 替换、qbar、窗口绑定。qbar 分区只保留 Everything 后端的必要配置，不再包含外观字段。

翻译和 AI 页面上的“设置”按钮通过 AHK 消息打开独立设置中心；旧的 `pages/settings.js` 已按用户授权删除，不再被运行页面引用。

窗口绑定模式改为用户语言：

- `单个窗口`：只绑定当前窗口。
- `窗口组`：将当前窗口追加到已有绑定组。
- `同应用窗口`：按程序名和窗口类自动维护该应用的窗口组。

### Tab 功能

`CapsLock+Tab` 只调用热串替换路径。`math.ahk`、`jsEval.ahk` 和 `loadScript` 已在后续复核中按用户授权删除；动作名直接改为 `keyFunc_tabHotString`，不保留旧动作名迁移。

## 错误处理与状态规则

- WebView2 消息回调只解析、校验和排队，不同步创建其他 WebView2 或执行长时间网络/Everything 操作。
- 所有来自页面的数字、枚举和字符串字段在进入 AHK 运算前校验；非法值使用明确默认值并记录字段名，不记录字段内容。
- 页面关闭、隐藏、设置保存和配置外部重载都必须取消相关计时器并使旧请求失效；旧异步回调不能更新新页面。
- 日志只记录事件类型、计数、状态码和耗时；文本只记录长度或哈希，endpoint 只记录脱敏后的协议/主机/路径。

## 验证策略

项目 `AGENTS.md` 明确禁止编写测试、启动或运行脚本，因此本轮不新增测试，也不运行 AHK、JavaScript、安装器或程序。每个阶段使用以下静态验证：

- `git diff --check`。
- `rg` 核对旧入口、QStyle、数学计算引用和发布资源清单。
- INI section/key、页面消息类型、AHK 函数名和 `#Include` 路径的交叉核对。
- PowerShell 读取文件与 HTML/配置结构检查；提交前检查工作区和提交内容。

## 分阶段交付

1. **正确性与隐私**：窗口绑定修复、Everything 解码修复、输入校验、日志脱敏、运行时小变更不全量重载。
2. **配置与设置统一**：配置模块、Qbar 设置字段、QStyle/数学功能运行时下线、唯一设置入口和文档同步。
3. **结构拆分**：公共 WebView2 宿主、qbar 子模块、页面公共通信和清理旧重复代码。

每个阶段都保持可单独回滚，不改变 `capslock-plus/` 参考目录。
