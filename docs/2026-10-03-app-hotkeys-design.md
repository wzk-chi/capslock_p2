# 按应用覆盖快捷键与设置页设计

日期：2026-10-04

状态：实现依据；本 worktree 已接入运行时、配置保存和设置页交互。未编写测试、启动或运行脚本、删除文件或重新打包。

## 1. 目标和范围

快捷键以全局配置为默认行为，应用配置只记录需要改变的键。应用有配置时，逐键覆盖全局；未改动的键继续继承全局。全局后续改变时，继承项自动更新，应用明确设置过的项保持自己的行为。

首版覆盖两类已有能力：

- CapsLock 层：CapsLock 点按、CapsLock + 按键、CapsLock + 左 Alt + 按键；继续支持内置动作和录制发送键。
- 普通自定义快捷键：例如 Alt+C → Ctrl+C；支持在特定应用内新增、修改、拦截和保留应用原键。

Tab 替换内容、窗口绑定内容、翻译和鼠标参数仍使用各自配置，不随应用改变。首版也不加入窗口标题表达式、网站 URL 匹配、任意 AHK 脚本编辑或复杂宏。

| `lib/features/settings.ahk` | 快照、差异保存、录制、应用选择、外部修改冲突检查 | 扩展应用快照、编辑协议和选择器用途 |

## 3. 覆盖规则

### 3.1 配置的三层关系

`内置默认 → 用户全局覆盖 → 当前命中的应用覆盖`

解析单位是一个触发键，而非整套配置。应用配置缺少某个键时，取当前全局最终值；自定义快捷键连全局和内置行为都不存在时，保留原始输入。

例子（当前内置 `CapsLock+S` 为向左移动，`CapsLock+Q` 为打开 qbar）：

| 触发键 | 全局最终配置 | VS Code 配置 | VS Code 中结果 |
| --- | --- | --- | --- |
| CapsLock+S | 向左移动 | 发送 Ctrl+Shift+P | 打开命令面板 |
| CapsLock+Q | 打开 qbar | 未设置 | 打开 qbar，继承全局 |
| CapsLock+Alt+H | 向左选中 3 个词 | 禁用动作 | 拦截该组合，不执行动作 |
| Alt+C | 发送 Ctrl+C | 保留应用原键 | 交给 VS Code 原本的 Alt+C |
| Alt+Enter | 未配置 | 发送 Ctrl+Enter | 仅 VS Code 中进行映射 |

### 3.2 一行映射的状态

| 页面选项 | 持久化含义 | 行为 |
| --- | --- | --- |
| 继承全局 | 应用配置中不存在该键 | 跟随当前全局最终值 |
| 自定义动作 / 发送按键 | 应用配置中存在明确值 | 替换全局动作 |
| 禁用动作 | 明确的 `@block` | 拦截触发键，不继续执行全局动作 |
| 保留应用原键 | 明确的 `@native`，仅自定义快捷键 | 本程序不拦截该键，也不执行全局映射 |

“禁用动作”和“保留应用原键”需要使用不同文案和状态，不能共用一个开关。CapsLock 是本程序的键层前缀，首版不提供单行组合的原键透传；禁用 CapsLock 层动作仍保持层的拦截。已有 `keyFunc_doNothing` 继续按原来方式执行，并在 UI 中显示为无操作。

禁用一个应用配置，表示其全部覆盖暂时不生效，改用全局行为；它不表示禁用该应用内的整个快捷键系统。重新启用会恢复原有映射。删除配置也恢复全局。恢复继承从配置文本中移除对应条目，不删除任何文件。

应用显式选择了与全局相同的动作，仍是应用覆盖，不能自动去掉：用户可能希望在全局将来变化时继续保留该动作。只有“恢复继承”才能移除这个覆盖。

## 4. 应用配置归属

一份应用配置对应添加时选择的一个 EXE 文件。添加应用只使用文件选择器；选择文件后，以规范化的完整 EXE 路径作为固定身份，显示程序名称和文件名。界面不暴露额外的匹配规则、进程名模式或路径条件。

- 路径比较忽略大小写并统一分隔符。同一路径不能重复添加；再次选中时定位到已有配置。
- 不同路径下的同名 EXE 是不同条目，应用列表中显示文件名及所在目录以便区分。
- 按键时从前台窗口取得正在运行的程序路径，只应用路径完全匹配的那一份配置。进程信息无法取得或没有对应条目时使用全局配置。
- 应用升级后文件仍在原路径时继续使用原配置；迁移到另一目录时，需要添加新 EXE 文件并删除旧条目。文件不存在时保留条目，由用户决定删除；不尝试模糊匹配。
- 商店应用或共享宿主程序只支持能通过 EXE 文件选择和前台进程路径准确识别的应用。

“添加应用”直接打开 Windows 文件选择器，筛选可执行文件（`.exe`）。选中文件后生成一份新的草稿条目，显示名称默认为 EXE 文件名，保存后生效。重复选择已有 EXE 时切换到已有条目，不产生第二份配置。不枚举已打开应用、不手动输入名称、不编辑身份规则，也不改动窗口绑定。

## 5. 设置页布局

### 5.1 顶部“应用范围”与应用列表小窗

保留现有左侧设置导航和顶部“取消 / 保存”，将快捷键页主区域排列为：

```text
现有设置导航   快捷键                             取消  保存
               应用范围 [Visual Studio Code ▾]
               （小窗）全局
                 应用                 状态     操作
                 Visual Studio Code   已启用   删除  禁用
                 Google Chrome        已禁用   删除  启用
                 [添加应用]

               [CapsLock 层] [自定义快捷键]
               [搜索触发键或动作]                □ 仅看本应用修改

               触发键          最终动作           来源       操作
               CapsLock+S      Ctrl+Shift+P        本应用     编辑 / 恢复继承
               CapsLock+Q      打开 qbar           继承全局   编辑
               CapsLock+Alt+H  禁用动作            本应用     编辑 / 恢复继承
```

点击“应用范围”打开应用列表小窗。小窗第一项是“全局”，下方表格列出全部已添加的 EXE；程序名一行、文件名和所在目录作辅助说明，状态独立显示。点击“全局”或应用行切换到该范围；切换后关闭小窗。列表固定从范围入口打开，前台窗口改变不会自动切换设置范围。

每个应用表格行最右侧固定提供“删除”和“禁用 / 启用”两个按钮。“禁用”保留应用映射但让它暂时回退到全局，按钮随状态切换为“启用”；启用后恢复原映射。禁用状态仍可点击该行进入编辑。删除先确认，再从草稿移除此应用配置，保存后该应用恢复全局行为。全局项不能删除或禁用。

点击“添加应用”直接打开 EXE 文件选择器，选中后在草稿应用列表新增条目并切换到该应用；同一路径已存在时选中已有条目。保存一次提交应用列表、启用状态和键映射改动，顶部取消会放弃未保存的增删或状态切换。

内容分为“CapsLock 层 / 自定义快捷键”两个页签，防止现有较长的层映射列表与自定义列表上下挤占空间。CapsLock 层继续使用现有分类折叠；自定义快捷键用同一行样式，在页签工具栏提供“添加映射”。

### 5.2 列表和编辑

- 默认显示最终生效的映射，包含继承行。“仅看本应用修改”隐藏继承行，显示覆盖、禁用、原键和新增项。
- CapsLock 层的行集合来自支持的键位目录，而非应用覆盖项；没有全局值的已支持键显示内置无操作。
- 自定义快捷键的行集合为内置普通行为、全局配置和本应用配置的并集。应用新增的触发键也进入列表。
- 来源采用文字徽标：全局页为“内置默认 / 全局修改”；应用页为“继承全局 / 本应用 / 本应用新增”。不要仅用颜色表达。
- 继承行显示当前最终动作。编辑不会先复制整套全局配置；明确选择自定义后才为该键建立覆盖。
- 覆盖行在动作下面显示当前全局值，便于判断改了什么；禁用和保留原键也显示被覆盖的全局行为。
- 每个已改行都有“恢复继承”。应用新增的自定义快捷键使用“移除映射”，移除后原始输入恢复；有全局对应项时改为“恢复继承”。全局 CapsLock 行用“恢复内置默认”。
- 搜索匹配触发键、动作名和类别；分类固定按默认键位目录组织，避免自定义动作后行忽然换组。

单行编辑复用 `pages/dialog.js` 的对话框，标题包含应用范围和触发键。CapsLock 层触发键只读；动作可选择“继承全局 / 内置功能 / 发送按键 / 禁用动作”，复用现有动作列表和录制入口。自定义快捷键允许录制或输入触发组合，并选择“继承全局 / 发送按键 / 禁用动作 / 保留应用原键”。本应用新增行没有可继承值时不展示“继承全局”。

录制触发组合和录制发送键必须各有按钮、各有明确提示，不能让用户误把触发键录到结果里。修改触发键是一个原子操作：原来的覆盖移除、新的映射新增；变更完成前检查目标键冲突。

高级发送文本沿用当前 AHK Send 语法，以可折叠字段提供，主要页面显示中文动作和可读组合。自定义映射首版保持“发送按键”能力，不新增任意函数调用；CapsLock 层继续由现有 `keyFunc_*` 执行器处理。

### 5.3 保存、空状态和尺寸

- 使用现有顶部统一保存。切换应用或页签保留所有草稿；不自动保存，也不为每次切换弹确认框。保存一次提交本轮所有已编辑范围。
- 单行对话框“确定”只写入草稿；文件选择新应用、删除应用、启用或禁用也是草稿，保存后才生效。取消对话框不改变草稿；顶部取消按现有规则放弃尚未保存的修改。
- 保存成功提示“已保存，快捷键已生效”；具体冲突定位到应用和触发键；保存失败保留所有草稿。
- 新应用为空时显示继承的映射。勾选“仅看本应用修改”后显示“还没有应用专属映射”和“显示全部 / 添加映射”入口。
- 已禁用应用继续允许点击表格行并编辑，清楚标示“此应用已禁用，当前使用全局设置”；保存不自动将其启用。
- 复用 `pages/theme.css` 和现有字体、Lucide 图标、Toast、Dialog。实际页面不增加第二套配色或独立主题开关；共用状态徽标和控件样式放入共享样式，局部只放布局。
- 现有初始窗口为 820×620、最小 720×520。小窗叠在现有页面之上，不增加常驻应用侧栏或挤占映射列表宽度；小窗内表格在窄窗口下转换为逐项布局。

小窗以独立背景、边框、阴影和关闭操作与后方页面区分；焦点留在小窗时可逐个浏览配置，键盘 Escape 关闭小窗。

## 6. 持久化与兼容

建议继续保存到根目录用户文件 `capslock_p2.ini`，避免全局配置和应用配置分属两个文件导致保存不同步。这是小型设置数据，不需要数据库或 AppData；不接触现有历史、媒体等 `data/` 用户数据。

现有 `[Keys]` 和 `[CustomHotkey]` 保持为用户全局覆盖。新应用使用稳定 ID 与规范化 EXE 全路径。示例仅说明格式，不能作为用户数据写入默认配置或安装包：

```ini
[Keys]
; 原有全局键位格式保持兼容
caps_s=keyFunc_moveLeft

[CustomHotkey]
!c=^c

[KeyProfile:kp_6b890412afac4e96a2ec79f79bbd64ca]
displayName=Visual Studio Code
enabled=1
exePath=C:\Program Files\Microsoft VS Code\Code.exe

[KeyProfile:kp_6b890412afac4e96a2ec79f79bbd64ca:Keys]
caps_s=keyFunc_send("^+p")
caps_lalt_h=@block
; caps_q 不存在，所以继承全局

[KeyProfile:kp_6b890412afac4e96a2ec79f79bbd64ca:CustomHotkey]
!c=@native
!Enter=^{Enter}
```

键存在性是状态的一部分：缺少条目表示继承，不能用空字符串兼任继承或禁用。新增格式的空动作视为无效并指出具体键；原有空值沿用现有兼容行为，不在加载时改写用户文件。`@block` 和 `@native` 由映射解析器先解释，不传给 `RunConfiguredAction()` 或 `SendInput()`。

只接受约定的 `KeyProfile:<ID>` 元数据段和 `:Keys`、`:CustomHotkey` 子段；复用 INI 解析和原子写入工具，增加有边界的 schema，不把任意段名全部开放给设置页。未知字段保留在原文，不能因保存相关配置而清空别的配置段。

根 INI 可能含 API 凭据。快捷键快照和可选后续导出只能包含快捷键相关字段；不能把整个 INI 发往网页预览或作为发布资源。新增应用设置不改变安装目录可写要求；不可写时显示明确保存失败并保留草稿，不静默迁移到 AppData。

首次加载直接把原有配置视为全局，无需文件迁移，没有应用配置时行为保持原样。应用记录只来自用户操作；不在 `capslock_p2-default.ini` 或安装包中增加个人应用名称和路径。

## 7. 运行时方案

建议新增 `lib/input/appProfiles.ahk`，集中负责应用匹配、不可变配置快照、逐键解析和来源信息；所有 AHK 实现仍放在 `lib/`。

### 7.1 CapsLock 层

保留一次性的完整静态注册和 `$` 保护；不要每次切换应用重新注册整套键位。`RunLayerAction(actionKey)` 获取此次按键的前台窗口快照，匹配应用并返回最终动作或禁用状态，再复用已有动作执行器。

按住 CapsLock 后切换前台应用，下一次组合键以当时前台应用为准，已经执行中的动作不改变目标。CapsLock 点按的例外：在按下时记录目标应用，松开时使用该快照；如果松开时目标窗口已经不同，取消点按动作，避免切换应用时误触。

无论是否禁用，层内组合都标记为已使用 CapsLock，释放时不能再误触点按动作。已在运行的剪贴板、窗口或面板动作继续使用自己的目标快照，不在其内部再次选择应用。

### 7.2 自定义快捷键

- 建立所有内置、全局和应用自定义触发键的并集，每个规范化触发键只有一个注册入口。
- 使用 AHK v2 官方 `Hotkey()` / `HotIf()` 条件机制。当 CapsLock 层未激活、未录制且最终行为为发送或拦截时，条件成立。
- 最终为 `@native` 或完全无映射时条件不成立，由系统正常传递原键；不能先拦截再 `SendInput()` 模拟原键，否则无法准确保留原有行为。
- 将现有 Ctrl+V 默认处理作为普通内置行为接入同一入口：应用覆盖优先，其次用户全局映射，最后原有系统剪贴板处理。其 `@native` 也要使入口完全不拦截；移除覆盖则重新使用原有处理。
- 在设置录制阶段使用现有 `InputHook`，暂时抑制业务映射，避免按下录制键时启动功能。录制完成、取消、失焦和关闭都恢复业务条件。
- 注册统一采用键盘 hook 和 `$` 防止发送结果重新触发本程序。条件检查使用真实物理 CapsLock 状态，与 `CapsLockLayerActive()` 对齐，不能仅依赖可能延迟清理的 `CapsLockHeld`。

触发键规范化需要消除大小写、等价键名和修饰键顺序产生的重复；左右修饰键明确区分。首版支持普通按键组合，保留现有合法高级触发串的兼容路径；含 `~`、`*`、`up`、自定义 `&` 组合等复杂语义不能通过简单去前缀强行合并，需按原语义建模。无法可靠解析或与新配置重叠的旧条目显示为高级条目，在解决冲突前阻止对其进行相互覆盖的新增操作，不能静默跳过。

物理 CapsLock、Alt+CapsLock 入口以及层内触发由键层拥有；普通映射编辑器不能重复注册这些入口。当前属于其他模块的热键在扩展前需要汇总所有权，不能让一个配置条目关掉另一个模块的独立注册。

### 7.3 性能、焦点和应用变化

不进行周期性枚举窗口。按键时从前台 HWND、PID 获取应用，短期缓存进程名和路径；缓存结合进程生命周期信息防止 HWND/PID 复用，并在配置版本变化时失效。`HotIf` 只做快速身份查询和内存匹配，不读 INI、不打开 WebView2、不请求网络。

条件判断和回调可能跨越焦点变化。回调执行前校对 HWND/PID：前台改变时重新解析当前目标一次；如果新目标不需要拦截则不向它补发旧动作，本次已被 hook 消费的输入直接放弃。宁可极少数切换瞬间丢弃一次按键，也不把上个应用的动作发送到新应用。后续按键按新应用正常解析。

保存配置或外部修改产生一份新版本快照。先完整构造并校验，再切换活动快照；只有普通触发键的并集变化才调整注册。应用匹配条件或动作改变不要求重载整个程序。

设置和其他本程序面板也是实际前台窗口；不把它们解释成上一个外部应用。设置录制期间暂停业务映射，其他时候按未匹配应用的全局规则处理。

## 8. 设置通信与保存边界

快照分别传递全局最终值、全局用户覆盖、应用元数据和稀疏应用覆盖，不能只传已经展开的有效动作。派生来源和全局参考值可以单独返回，避免页面猜测继承状态。

保存协议保留现有设置消息入口，增加快捷键操作列表：`createProfile`、`updateProfile`、`removeProfile`、`setOverride`、`removeOverride`；每项携带稳定配置 ID、类别和规范化键。恢复继承使用显式移除操作，不使用“新值等于全局”或空字符串推断。

冲突检查比较字段存在性和内容：原来缺失与明确设为同一个全局值也属于不同状态。全局变化而应用草稿只新增独立覆盖时可继续保存；若正在恢复继承而基准全局值已变化，应展示将要继承的新值，让用户明确处理，避免误以为恢复到了旧值。外部删除应用条目或修改同一覆盖时阻止覆盖保存并保留草稿。

应用配置以 EXE 全路径确保唯一，同一路径创建时复用已有条目；对动作做 `keyFunc_*` 可调用性和发送格式校验；对触发做同范围重复、层入口冲突和高级语义重叠检查。同一个触发在不同应用中出现是正常覆盖，不应报错。

全局和应用修改在同一份 INI 原文上构造一个候选文档，一次原子写入，其他配置字段不受影响。先保存完整旧快照和原文，验证候选配置并预检注册参数；磁盘提交和运行时注册切换均成功后才返回“已生效”。若注册失败，恢复旧运行时和原文；若恢复写入也失败，明确返回“已写入但未生效”，保留可恢复信息并允许重试，不能吞掉错误或只报告成功。WebView2 回调里的保存和选择器工作沿用 `SetTimer(fn.Bind(...), -1)` 延迟处理，避免回调中同步等待新的 WebView2。

## 9. 实施顺序和人工核对项

1. 增加应用配置 schema、读取和稀疏覆盖解析；现有全局配置直接兼容。
2. 接入 CapsLock 层和点按目标快照，再统一普通快捷键与 Ctrl+V 的注册所有权。
3. 扩展设置快照、草稿操作、保存事务和外部冲突检查。
4. 改造快捷键页，复用主题、Dialog、录制与应用选择的数据来源。
5. 在用户另行允许运行后，人工核对下面的行为；本次不创建自动化测试、不启动脚本。

人工核对关注：无应用配置时旧行为一致；应用新增/覆盖/禁用/原键各自生效；恢复继承后跟随全局；禁用和删除后恢复全局；EXE 全路径归属唯一；小窗点击条目正确切换范围；启用按钮互换为禁用；删除需确认；切换应用不串键；发送结果不递归；Ctrl+V 的内置和覆盖行为一致；录制不触发动作；跨应用草稿不丢失；外部冲突定位准确；注册或写入失败不显示成功；720×520 与深浅色均可用。

开发只修改相关模块，不写入或修改 `capslock-plus/`，不清理当前工作区已有改动，不自动重新打包。
