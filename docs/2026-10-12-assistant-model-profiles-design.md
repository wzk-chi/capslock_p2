日期：2026-10-12

状态：已生成独立实现候选，静态检查通过，尚未启动或通过运行验收。原版和构建材料保存在助手目录的 `_维护备份`；较早的共存候选和旧说明已移入 D 盘回收站；实际设置和结果数据保留。用户在实施期间明确要求“请无视云端同步”，因此本次范围收窄为本地模型组、全局切换和桌面请求快照；云端流程按原实现保留。

## 1. 目标与推荐方案

支持用户配置多组完整的 URL、API Key、模型名称。按 Ctrl+Shift+C 在配置组之间循环切换，下一次请求使用所选组的全部三项参数。

推荐第一版采用本地 JSON 配置，不新增可视化配置管理界面：

- `model_profiles.json` 保存模型组定义，用户手动编辑。
- 现有 `desktop_settings.json` 增加 `active_model_profile`，只用来记住上次选择的稳定 ID；原有公共设置继续保存在此文件。
- 切换通过已有 Windows 系统热键和主线程命令队列完成，移除旧 Shift+C 绑定及硬编码的四个服务预设。
- 每个请求固定使用启动时的配置快照；切换不会终止、重启或改变正在进行的请求。

相较原来的“只换地址和模型”，新的单位是一套可独立使用的连接配置。不同组可以使用相同地址、不同 Key 或模型，也可以连接不同服务。

## 3. 用户配置格式

文件位于助手 EXE 同目录：`D:\work\招聘\笔试\model_profiles.json`。UTF-8 编码，允许 UTF-8 BOM，使用严格 JSON，不支持注释。

示例仅含占位值，不写入真实凭据：

```json
{
  "version": 1,
  "default_profile": "primary",
  "profiles": [
    {
      "id": "primary",
      "name": "常用",
      "base_url": "https://service-a.example/v1",
      "api_key": "填写服务 A 的 Key",
      "model": "填写服务 A 的模型名"
    },
    {
      "id": "backup",
      "name": "备用",
      "base_url": "https://service-b.example/v1",
      "api_key": "填写服务 B 的 Key",
      "model": "填写服务 B 的模型名"
    }
  ]
}
```

| 字段 | 规则 |
| --- | --- |
| `version` | 第一版固定为整数 1；未知版本报错 |
| `default_profile` | 必须引用列表中存在的 ID；首次使用或已保存 ID 被移除时，使用此组并明确提示 |
| `profiles` | 非空数组；数组顺序就是切换顺序 |
| `id` | 非空、唯一、区分大小写的稳定字符串；改名字或调整顺序时保留 ID |
| `name` | 非空显示名称，用于切换提示；名称可以修改，不承担身份匹配 |
| `base_url` | 非空的绝对 HTTP/HTTPS 地址，按现有兼容接口地址语义校验，不猜测或自动改成其他服务 |
| `api_key` | 必须明确给出字符串；无鉴权本地服务允许显式空字符串；不得继承上一组 Key |
| `model` | 非空模型名称；不得继承上一组模型 |

整个文件校验成功后才发布新组集合。重复 ID、重复 JSON 字段、错误类型、无效默认组或任一不完整条目均使本次读取失败，不静默跳过坏条目、不修补成其他服务。

第一版只为组配置这三项连接参数。提示词、温度、输出长度、超时、视觉输入及连续截图等参数继续共用原有设置，不同时引入参数覆盖、自动故障切换或按任务选择模型。

## 4. 两个文件的职责

### 4.1 组定义由用户管理

程序只读取 `model_profiles.json`，快捷键切换不重写它。这样用户编辑列表时，不会被保存当前选择的操作覆盖。

每次切换、启动请求或连接测试之前重新读取并校验文件；不增加轮询、目录监听或逐字符读取。用户修改文件后保存，下一次相关操作即可读取，无需为了改组重启程序。

### 4.2 当前选择由程序保存

在现有 `desktop_settings.json` 增加：

```json
{
  "active_model_profile": "backup"
}
```

这只是新增字段示意，不能用这段内容替换完整设置文件。程序保存时必须保留原有公共设置和同步账户字段。

现有顶层 `base_url`、`api_key`、`model` 可继续作为当前组的派生镜像，供原有显示和设置格式使用。多组模式中，它们不再是选择或覆盖模型组的来源；当前连接三项始终取自有效组定义。

所有保存入口统一保留 `active_model_profile`。该内部选择字段不作为模型 API 请求体参数发送；云端协议与参数同步本次不处理。

### 4.3 未配置与配置损坏

- 启动时文件不存在，且设置中没有已保存的模型组 ID：沿用原来的单组设置，不自动生成、导入或覆盖用户文件；按切换快捷键提示先配置模型组。
- 启动时已经保存过模型组 ID，但组文件缺失：提示恢复模型组文件，暂不提交模型请求；不将文件丢失解释为用户要退回单组模式。
- 启动时文件存在但无效：给出可定位到文件、字段或行号的提示，模型请求暂不可用；不悄悄使用默认地址或旧 Key。
- 运行中已经启用多组后，文件缺失或读取失败：保留当前内存组供界面显示，本次切换或新请求停止并提示修正文件；不退回旧单组参数。
- 修正文件后，下次切换或请求重新读取；原来正在执行的请求不受文件编辑影响。

## 5. Ctrl+Shift+C 的切换行为

### 5.1 全局入口

按全局快捷键设计：助手在后台或最小化到托盘时也能切换。该组合由用户明确指定，因此助手运行期间，浏览器等应用原有的 Ctrl+Shift+C 不再优先接收这次输入。

复用现有 `RegisterHotKey`，注册精确的 Ctrl+Shift+C，使用 `MOD_NOREPEAT`。不安装新的低级键盘钩子，不使用通配修饰键，也不通过钩子强占注册失败的组合。

分发路径为：

`WM_HOTKEY → 现有命令队列 → 主线程处理 cycle_model_profile → 模型组服务`

使用独立稳定的热键 ID 和固定命令标识，不根据显示名称分发、不接受配置文件中的函数名或代码。Tk 侧不重复绑定 Ctrl+Shift+C；旧 Shift+C 入口移除。

注册失败时提示该组合不可用，详细错误写入日志；不临时改用其他未约定快捷键。原有 AHK 拦截与录制可先于系统热键处理输入，不用额外监听绕过它们。

### 5.2 循环规则

- 正常情况：从当前 ID 在最新列表中的位置开始，选下一项，到末尾后回到第一项。
- 首次在运行中创建配置文件：本次先启用 `default_profile`，不跳过用户指定的默认组。
- 当前 ID 已被用户移除：本次选默认组，并提示原组已移除。
- 只有一组：同步这一组的有效参数并提示“只有一组模型配置”；不伪装成切换了另一组。
- 每次完整点按推进一次；按住不连发，不用固定去重时间吞掉快速但有意的连续点按。

### 5.3 切换作为一次完整操作

1. 读取并验证整个组文件。
2. 确定目标组，构造包含 ID、名称、URL、Key、模型的不可变快照。
3. 读取当前持久化设置，保留其他字段，更新当前 ID 和三项派生值。
4. 在同目录写入完整临时文件，再原子替换设置文件；写入失败时本次切换不发布。
5. 一次替换内存中的活动组对象，再同步界面显示与状态提示。

请求只读取活动组快照，不拼接三个可能处在不同更新阶段的界面变量。保存失败时仍保留原组，不能出现“界面显示备用、重启后仍是常用”或新地址配旧 Key。

切换不调用 `save_current_settings()`、`analyze()`、云端模型同步或自动连接测试；它只提交当前组选择。耗时的连接检查由用户明确发起。

## 6. 请求、界面和云端边界

### 6.1 请求快照

新请求开始时，先验证当前 ID 在最新文件中仍有效并刷新该组完整快照，再与公共设置合成请求参数；ID 被移除时提示先切换选择，不在提交请求时静默改用其他组。

解析、连接测试、视觉输入失败后的 OCR 降级及同一任务内的后续调用，都使用该任务启动时的同一配置快照。Ctrl+Shift+C 不修改任务 generation、取消事件或已有线程的设置对象。

例子：A 组请求正在生成时切到 B，当前请求继续由 A 完成，下一次新请求使用 B；结果中的模型信息记录实际运行的 A，不根据此时界面显示的 B 回填。

连接测试也在创建线程前捕获快照，不继续从变化的 `self.settings` 读取连接参数。快照中的 Key 不出现在日志、进度信息或结果元数据中。

### 6.2 无配置管理页面，但有明确反馈

不新增模型组编辑器。保留现有公共参数设置；多组模式下，URL、Key、模型字段显示当前组的值，禁用直接修改，并说明请编辑 `model_profiles.json`。

切换后更新现有状态栏和托盘提示，显示组名称及模型，例如“已切换到备用 · model-b，下次请求生效”。不显示 Key，不弹出设置窗口或抢占其他应用焦点；即使系统通知被关闭，打开助手后仍能看到当前组。

### 6.3 云端范围调整

用户在实施期间明确要求“请无视云端同步”。原先停用云端模型参数双向同步的建议退出本次范围，既有同步函数、服务端协议、手机和网页请求入口均保留，不实施也不验收新的云端行为。

本地桌面连接统一从活动组快照读取，模型组文件不进入新的上传流程。现有保存和解析入口包含的同步调用仍按原实现执行，本次不承诺云端配置隔离或手机端模型组切换。

## 7. 实现范围与分阶段方式

当前没有完整助手源码，实施应从已确认版本的 EXE 和可审查 Python 代码片段构建新候选，保留原版与现有共存候选。

建议将本地组解析、校验、选择和活动状态持久化集中在一个模型组组件内。界面、热键和请求入口调用该组件，不各自解析配置或拼接连接参数。只复用原程序已有的标准库和系统热键能力，不为此引入新运行依赖。

| 修改范围 | 目的 |
| --- | --- |
| 模型组组件及设置保存 | 独立文件、完整校验、稳定 ID、原子保存和恢复选择 |
| `current_settings()` 及启动初始化 | 连接三项取自同一组快照，保存时保留选中 ID |
| 系统热键注册、`_window_proc()`、`process_ui_commands()` | 精确 Ctrl+Shift+C，统一主线程入口 |
| `bind_hotkeys()` / `cycle_preset()` | 移除 Shift+C 和旧硬编码预设，接入新循环行为 |
| 请求入口与连接测试 | 固定任务快照，保留正在进行的请求 |
| 模型设置窗口与桌面连接读取 | 连接三项只读显示，并统一从活动组读取 |

先完成配置组件、持久化及旧入口替换，再接系统热键与请求边界；实施中保留上一个共存候选，整个本地模型组组件编译后生成一个新的独立候选。按已验证原版和明确补丁清单重新构建。

修改范围比上一个“只换全局键盘入口”的候选更大，不能只替换一个预设函数后宣布完整支持。归档结构及代码范围静态核验通过后，仍需用户实际启动与行为验收。
