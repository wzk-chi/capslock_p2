## 1. qbar 路径应由程序管理

**原问题成立，但原解决方向不符合用户意见。**

证据：

- [settings.html](../pages/settings.html) 第 282–285 行暴露 `esPath`、`everythingPath`、`esInstance`、`esMaxResults`。
- [qbar_everything.ahk](../lib/qbar_everything.ahk) 的 `QbarEsExe()`、`QbarEsEverythingExe()` 先返回缓存，再读取配置；路径不会因保存自动刷新。
- 设置页实际调用 `ReloadSettings()`，不是 `ApplySettingChange()`。两条路径都未清理路径缓存；上一轮只引用后者，调用链说明不完整。
- [capslock_p2.iss](../tools/capslock_p2.iss) 已明确分发 `resources/es.exe` 和版本化目录中的 Everything。

修订方案：

1. `es.exe` 使用程序资源目录；内置 Everything 使用与发布清单一致的资源定位规则。资源缺失时给出清晰提示。
2. 从设置页和可写字段白名单移除两个路径字段；运行时停止读取对应覆盖项。不能只隐藏输入框而继续接受保存消息。
3. 默认配置、示例和当前使用说明同步调整。个人 INI 中已有字段保留原文，但不再生效，不自动清理。
4. 保留“已有用户 Everything 可用则优先使用”的后端选择行为；固定的是程序依赖的位置，不是强制每次启动内置实例。
5. 固定资源定位可以保留简单缓存，不需要为用户编辑路径设计缓存重置。

用户批注明确针对路径。本文另建议把内置 `esInstance` 固定为程序内部名称，它属于实例隔离细节；这属于方案建议，不冒称用户已单独要求。`esMaxResults` 仍是有实际用途的偏好，可保留，范围为 1–500。

静态验收：运行代码不再读取两个路径覆盖项；页面和白名单一致；资源定位与安装清单一致；不增加个人配置迁移。若同时固定实例名，应同步核对启动、查询和退出使用同一名称。

## 2. 多行配置必须编码，但不能全局替换反斜杠

**确认是配置往返缺陷，应优先修复。**

证据链：

- [settings.html](../pages/settings.html) 的提示词和 Tab 替换使用 `textarea`，草稿直接保存 `.value`。
- [settings.ahk](../lib/settings.ahk) 的 `SettingsCollectSectionChanges()` 只转换字符串，没有处理值中的 CR/LF。
- [config.ahk](../lib/config.ahk) 的 `ConfigSetIniValue()` 直接拼接 `key=value`；`ConfigParseIni()` 按行解析。
- 因此多行内容的后续行可能被忽略，也可能被解释为新的键或节，而不只是显示时少一个换行。

原建议“全部配置统一做 `\n` 解码”过于宽泛。路径、正则和提示词里的字面反斜杠必须保留；[core.ahk](../lib/core.ahk) 的 `HotStringUnescape()` 已对 TabHotString 实现 `\n` 和 `\\`，再解码一次会改变结果。

修订方案：在配置存储边界集中定义**字段级 codec**，页面使用实际文本，磁盘值始终占一个物理行。

| 字段类型 | 处理要求 |
| --- | --- |
| `TabHotString` 值 | 兼容旧 `\n`、`\\` 语义；读取时只解码一次，保存时对实际文本编码一次；迁移调用点后不再由热串执行路径二次解码 |
| `LLMTranslate.systemPrompt`、`QAI.systemPrompt` | 使用明确可识别的单行编码格式；建议带版本标记的 JSON 字符串封装，复用现有 JSON 库；未标记旧值保持原样 |
| 路径、URL、快捷键等单行字段 | 保持原有反斜杠；拒绝物理 CR/LF，不静默写成多行 |

提示词封装需定义标记冲突和无效封装的处理：只有完整合法封装才解码，新输入中的字面标记也应能往返。不要把所有旧提示词里的 `\n` 擅自解释成换行。应复用已有 JSON 标量包装方式，不能假设当前 `JSON.stringify` 支持裸字符串。

所有配置写入入口共享规则，包括设置页批量保存、`ConfigSet()` 和 qbar 内联配置。比较默认值时使用相同的逻辑文本表示，避免因编码形式不同产生多余覆盖项。INI 节名和键名也应在存储入口校验，不能只依赖设置页面的白名单。

静态验收：逐条推导多行文本、字面 `\n`、反斜杠、Windows 路径、引号、空值及首尾空白的往返结果；确认保存、快照和业务读取之间只有一层编码/解码。这是人工代码推导，不新增或运行测试。

## 3. 把回调外执行与真正异步区分开

**调度改进合理，但上一轮描述需要纠正。**

证据：

- [dictionary.ahk](../lib/dictionary.ahk) 第 217 行起的消息回调同步执行查词和联想查询；联想包含前缀、包含和模糊匹配。
- [dictionary.html](../pages/dictionary.html) 已有 120 毫秒输入防抖；`DictionarySuggestCollect()` 在候选够用时跳过后续查询。不能把这些已有措施说成缺失。
- [qbar_everything.ahk](../lib/qbar_everything.ahk) 已由 `SetTimer(QbarEsFlush, -100)` 调度，并在结果回填前校验序号和可见性。
- 历史问题是内部曾使用同步 `RunWait()` 和最多十次 `Sleep(1500)` 重试。15 秒只是显式休眠的合计，未包含进程等待；AHK 的 Sleep/RunWait 期间可以响应部分其他线程事件，不能据此断言整个程序必然冻结 15 秒。当前整改已改为带期限的异步作业。

词典方案：消息回调负责解析和入队；用具名定时器合并最新联想请求，并携带查询序号和面板会话标识。清空输入、隐藏、重新打开、显式查词时使旧联想失效，页面也要校验返回结果是否对应当前查询。保留现有防抖和分层查询。

定时器仍在同一个 AHK 进程中执行，同步 SQLite 查询不会因此成为后台工作。第一阶段只保证 WebView2 回调快速返回及结果不过期，不承诺已消除数据库耗时。没有运行时数据前，不引入工作进程或盲目重建词库索引。

Everything 方案：复用已有 `es.exe`，把探测、查询、冷启动等待改为同一个有期限的异步作业流程。每个作业记录查询序号、进程句柄、输出位置、期限和完成状态；定时器短轮询，只有进程完成且序号仍有效时才读取、解析、回填。查询为空或正常零结果不等于索引尚未就绪。

实现时优先核对当前 es.exe 的官方导出能力，若足够则直接调用并导出结果；当前尚未核实具体开关，不在文档里虚构命令。若必须重定向，应正确处理 Windows 参数和 shell 转义，不能继续假设给任意查询加双引号就足够。

隐藏、退出、新查询和超时都要定义终结路径。限制并发查询数，保证回收自有查询进程和句柄；不要终止用户已有的 Everything。当前 `QbarEsBundledStarted` 同时表示“探测到实例”和“本次启动”，应区分实例可用性与所有权后再决定退出行为。临时输出的读取时机、异常路径和资源回收必须明确；本次审查不创建或删除这些运行时文件。

静态验收：WebView2 查词/联想回调内不再执行 SQL；Everything 查询链不再依赖 `RunWait` 或长 Sleep 循环；所有完成路径都受序号、可见性和期限约束。实际交互流畅度仍需在允许运行的环境另行确认。

## 4. LLM 校验与日志：缺陷成立，避免借此改变服务兼容性

证据：[llm.ahk](../lib/llm.ahk) 的 `LLMBuildRequest()` 第 280 行在校验前执行 `timeout + 0`；设置页超时输入是普通文本，保存路径不做类型校验。`LLMStreamComplete()` 第 686–687 行把完整 `errorText` 拼入日志，而它可能来自服务端错误正文或 COM 错误描述。

“存在泄露路径”成立；没有证据证明已有日志实际泄露了内容。界面可以显示必要的服务错误信息，文件日志应记录本地定义的错误类别、请求 ID、HTTP 状态、耗时和长度，避免记录原始错误正文或任意异常消息。端点脱敏也不能只去掉查询串而保留可能存在的 URL 用户信息。

修订方案：

- 保存、未保存草稿的连接检查、运行时请求使用同一组纯值校验函数；函数接受候选值，不能只读取全局 `Config`，否则覆盖参数会绕过校验。
- 超时使用整数和现有 1000–120000 毫秒范围；转换失败在边界处理。界面明确指出字段问题，外部 INI 的非法值使用有文档依据的默认策略。
- temperature 保留“空值时不发送”的语义；校验数字，不凭空为所有兼容服务套用某一家供应商的范围。
- `maxInputTokens` 保留现有未限制语义或明确另做产品变更，不能把原来空值/0 的行为悄悄改为最小 1。
- 必填项按用途校验。保存其他偏好时允许 LLM 尚未配置；真正调用服务时才检查必要的连接信息。API Key 是否必需不因此次整理擅自放宽或收紧。
- 日志的错误类别由代码枚举生成，不从服务端任意字符串直接复制。

另一个与类型边界直接相关的复核发现：`LLMMsgField()` 将非字符串的数值 1/0 映射成 `"true"`/`"false"`。窗口捕获页面发送的是数字 `number`，因此编号 1 会被 `SettingsCaptureWindow()` 的数字正则拒绝。后续集中消息读取规则时应使用数字、布尔、文本各自的读取方式，不能复用一个把数值和布尔混淆的字符串转换器。不要修改第三方 JSON 库来掩盖调用方问题。

静态验收：所有数值转换之前都有明确校验；草稿连接检查走同样的规则；错误日志没有原始正文；数字 0/1 与布尔值按字段契约区分。

## 5. 无变化保存：先保证幂等，再应用差异

**确认存在多余工作，而且比原审查描述更具体。**

证据：

- [settings.ahk](../lib/settings.ahk) 的 `SettingsApplyDraft()` 无条件调用完整重载、AI/翻译通知和快照推送。
- [llmTranslate.ahk](../lib/llmTranslate.ahk) 的 `LLMTranslateOnSettingsSaved()` 在面板可见且有文本时会再次请求翻译，因此保存无关偏好也可能重复请求 API。
- [config.ahk](../lib/config.ahk) 的 `ConfigSetIniValue()` 用 `StrSplit` 拆行后，为每个元素重新追加换行。已有末尾换行会产生尾部空元素，使相同赋值也可能增加空行。批量写入逐键重复此过程，文本比较会把这些空行当成变化。

因此，“已有函数能可靠避免无变化写入”不成立，仅添加 `changed` 返回值不够。

修订方案：

1. 修正写入器的末尾空行处理，保证同一逻辑更新重复应用不再改变输出。尽量保留注释、顺序和未知配置；解析读最后一个重复键、写入只替换第一个键的语义也须统一。
2. 将结果区分为 `fileChanged` 和 `effectiveChanges`。清除与默认值相同的覆盖项可以改变磁盘文本，但无需触发业务重建。
3. 保存草稿时识别真正修改的字段，防止完整旧快照覆盖期间发生的托盘、热键或外部配置变更。可使用打开时的基线和修改字段集合，不需要复杂的版本管理框架。
4. 持久化成功后再更新内存、文件时间和受影响的派生状态；同一个处理器每批最多执行一次。无有效变化时只确认保存，不重注册快捷键、不重启定时器、不重发翻译。
5. 配置加载与运行时应用共用差异派发。外部文件重载可以重新解析一次，再比较有效值；不要依次对所有字段调用会写文件的 `ConfigSet()`。
6. 语言切换、首次补齐服务配置后继续待处理请求、`hideOnBlur` 变化等必要通知保留，并按具体变化触发。无关字段变化不取消或重启进行中的请求。

静态验收：能区分“无变化”“只有持久化文本变化”“有效配置变化”；无变化保存不产生文件或业务副作用；配置保存失败不留下未持久化的内存新值。

## 6. schema 集中：统一数据规则，保留界面职责

**维护成本问题成立，但不必生成整套 UI。**

证据：[config.ahk](../lib/config.ahk) 的 section 补全列表，与 [settings.ahk](../lib/settings.ahk) 的 `SettingsConfigSections()`、`SettingsIsDynamicSection()`、`SettingsAllowedKey()` 重复描述相同配置。`SettingInteger()`、`SettingNumber()` 仍在 core 中直接读取全局配置。

建议在 `lib/` 的配置边界提供一份轻量字段元数据：section、key、类型、空值含义、范围/枚举、codec、是否可由页面写入、关联的运行时处理组。默认值继续来自 `capslock_p2-default.ini`，不要在 schema 中复制完整默认配置。

已有读取、保存和快照函数消费这份元数据；页面可接收约束和枚举用于交互提示，AHK 仍负责最终校验。动态 section 支持任意合法键，并保留“空覆盖项屏蔽默认条目”的语义，不能将所有空值统一删除。

设置页面 ID 与 INI section 并非一一对应：例如 mouse 页面修改 Global，translate 页面涉及多个 section。页面路由单独维护小型元数据，并与配置字段关联；不强行把所有导航或布局塞进配置 schema。

静态验收：新增静态字段不再同时修改多套白名单；页面不接受已收回的路径字段；schema 不拥有 GUI 对象或副作用；运行时处理通过单独派发层执行。

## 7. PanelHost：移除镜像状态，保留有意义的包装

**收敛方向合理，应分面板实施。**

证据：[panelHost.ahk](../lib/panelHost.ahk) 已拥有 GUI、controller、WebView、pageReady；AI、翻译、词典、设置和 qbar 又保存对应全局镜像并通过 `*SyncHost()` 复制。导航成功状态也被公共层和功能层重复赋值。

其中，`PanelHostEnsure()` 第 72 行的局部 `callbacks` 未使用，`focusTimer` 布尔字段目前只写不读，可清理。`focusMonitor` 保存计时器回调，用于停表，是必要状态；导航和消息回调引用也不能仅因没有普通调用就认定无用。

修订方案：

- 宿主原生资源和真实可见/就绪状态只保存在 Host；功能侧通过 Host 或只读访问函数取得，逐步消除 `*SyncHost()` 和可变镜像。
- 将共同的 ensure/retry/error 机制集中，但保留按面板配置参数的小型入口函数；这些包装提供业务含义，本身不构成冗余。
- 保留 qbar 的无边框定位/行数尺寸、词典边框处理、设置页未保存确认、AI 首次激活宽限及窗口尺寸记忆、各面板的失焦策略。
- 业务待处理文本、请求 ID、历史和请求运行状态继续由业务模块负责。显示意图与窗口实际可见状态不相同，不能在初始化期间简单合并一个布尔变量。
- 创建失败、隐藏和销毁时分别定义定时器、事件订阅和控制器处理；使用现有 WebView2 绑定提供的解除订阅/关闭能力，不另写 COM 封装。回调引用与 Host 的相互引用也纳入销毁审查。
- 不调整旧焦点修复、DPI 或窗口定位来追求统一代码形状。每迁移一个面板就静态检查所有外部调用，尤其是 `keys.ahk` 的窗口判断。

静态验收：业务读取不依赖过期镜像；同一导航结果只由宿主更新一次；失败后可重试；关闭后没有旧业务回调更新新会话。实际焦点与窗口表现未运行验证，不能只凭代码缩短宣称等价。

| [core.ahk](../lib/core.ahk) 第 51 行直接重建热串，第 60 行又安排相同工作 | 保留一次启动初始化，移除纯转发定时器入口 | 配置变化后的热串重建仍保留 |

剪贴板尤其需要谨慎：无选区分支目前在解除监听挂起之后才恢复，且外层恢复不在 `finally` 中；异常或用户的新复制都可能让结果不符合预期。建议将该分支恢复放入 `finally`，恢复进入前的监听状态，并用剪贴板序号避免覆盖用户的新内容。有选区分支可移除多余的外层快照/恢复，但保留读取和粘贴各自需要的保护。不顺带改变 UIA 优先及 Ctrl+Insert/Ctrl+C 回退策略。

上述修改优先复用已有实现；不为了几十行共享代码另引入依赖或复杂抽象。

## 9. 补充纳入的五项建议

根据用户后续要求，以下五项纳入文档中的后续修改范围。取舍以减少重复维护和保持行为稳定为依据，不将未经测量的优化收益写成已确认的性能问题。

### 9.1 qbar 配置索引：增加轻量缓存，放在增量配置之后

**决定：建议实施，中优先级。**

证据：[qbar_index.ahk](../lib/qbar_index.ahk) 的 `QbarConfigItems()` 每次构造配置条目，并解析运行目标和图标键；`QbarFilterItems()` 经 `QbarAllItems()` 重复执行它。开始菜单已有独立缓存，不需要再重复缓存一份开始菜单列表。

建议维护一个只针对配置的索引，包含展示条目和按短键查找的数据。首次使用时构建；`QRun`、`QWeb`、`QSearch` 或界面语言的有效变化使其失效。重建放在下一次使用时，同一批保存只失效一次；不要缓存每一种用户查询结果，也不增加后台扫描定时器。

过滤和执行共用索引规则，但必须保留当前各 section 的命令优先级、别名、内置命令让位规则及默认搜索随语言变化的行为。同名短键不能因 Map 覆盖顺序改变执行目标。空配置值是否占用短键，当前存在不同函数处理不一致的情况，应单独明确规则，不能借缓存悄悄改变它。

缓存只承担配置解析；文件存在性在执行时仍需核对。文件夹列表、Everything 结果、图标发送状态各有自己的生命周期，不并入这个缓存。具体延迟改善没有实测，文档不承诺数值。

静态验收：普通输入查询不再重建配置条目；配置和语言变化能够刷新索引；开始菜单缓存不重复；跨 section 同名条目和已失效文件不会因缓存改变命令分派规则。

### 9.2 窗口绑定：统一完整模式元数据，保留未绑定与捕获选择的区别

**决定：建议实施；消息类型修复优先，文案整理低优先级。**

证据：[windows.ahk](../lib/windows.ahk) 的 `WindowBindingDisplay()` 与 [settings.html](../pages/settings.html) 的 `renderBindings()` 各维护一份模式名称和说明；宿主快照中的 `modeLabel`、`modeDescription` 未被页面消费。

撤回“`binding.bindType || 1` 本身就是显示错误”的判定。下拉框可以表示下一次捕获方式，空绑定处页面也已显示“未绑定”。建议在宿主维护完整的模式列表（ID、名称、说明），随快照发送一次，页面用它生成选项和说明。当前绑定状态继续由 `bindType/items` 表达；未绑定时允许捕获选择默认模式 1，但不能据此显示成已经绑定。

先按第 4 节处理数值 1 被当成布尔值的问题，保持模式 ID 1–3 和绑定编号 1–10 的契约。顺带将编号 10 的快捷键标签显示为 CapsLock+0，与默认键位一致；这只修正显示，不改持久化编号。完整模式列表启用后，移除没有消费者的逐行重复标签字段。

静态验收：三种模式各有一个名称来源；每种选择仍发送正确数字 ID；空绑定与待捕获选择分开呈现；编号 1 和 10 的消息、显示及默认键位互相一致。

### 9.3 无调用函数：收缩内部死分支，保留扩展契约

**决定：建议在配置重构完成后实施，低优先级。**

对运行时 include 图、回调注册、动态调用、默认/示例配置、`userAHK/` 和文档进行交叉核对后再裁定。仅搜索 `函数名(` 会漏掉回调和 INI 动作，不作为删除依据；不读取或展示个人凭据来完成引用审查。

| 对象 | 建议 |
| --- | --- |
| `LLMAiChatComplete()`、`TranslateLlmComplete()` | 若最终仍无活动调用或公开扩展契约，移除这两个业务同步分支；保留连接检查实际使用的公共 `LLMChatComplete()` |
| `ConfigHas()`、`ConfigSectionExists()`、`ConfigWrite()`、`ConfigWriteBatch()` | 先完成 schema/保存入口收敛，再移除仍然只定义或仅内部互调而不可达的辅助链；不为保留函数而制造无意义调用 |
| `SettingNumber()` | 优先将有价值的数值校验逻辑吸收到接受候选值的统一校验器，消除未使用旧入口，避免先删后重写 |
| `keyFunc_*`、已注明兼容用途的助手、第三方库接口 | 不按仓内直接调用数量清理；保留既有扩展入口与库完整性 |

在变更说明中列出移除的内部符号及替代入口。若发现它实际是公开扩展接口，则保留或另行制定迁移，不把仓内无调用当成外部绝无依赖的证明。此项指编辑源文件中的函数定义，不删除源文件。

静态验收：被移除符号没有活动调用、注册或动态配置引用；连接检查仍能沿公共同步请求链到达实现；保留动作与用户扩展入口；不裁剪第三方库。

### 9.4 qbarDebug：移除无效诊断通信，保留 IME 控制

**决定：建议实施，低优先级，可与公共函数清理同批进行。**

证据：[qbar.html](../pages/qbar.html) 的 `qbarDebug()` 将输入值及 IME 事件内容发送给宿主；[qbar_panel.ahk](../lib/qbar_panel.ahk) 的 debug 分支只记录固定文字。当前收益很低，即使文件调试日志关闭，页面依然构造并发送消息。没有证据表明该分支把输入文本写入日志。

移除该函数、调用点及对应宿主分支；`querySerial` 和 `deferredQuery` 当前只服务于诊断内容，可在核对最终引用后同步移除。保留 `composing`、`event.isComposing` 判断、组合输入结束后的查询，以及宿主真正用于过期请求校验的 `QbarQuerySeq`/`QbarEsSeq`。不能将页面诊断计数与宿主请求序号一起清理。

保留有实际用途的 ready、query、execute、resize、hide 消息。若以后需要诊断，使用显式开关及不含原始输入的事件、数量和耗时，不恢复整段文本的诊断传输。

静态验收：页面不再发送 debug 消息；没有悬空诊断调用；IME 组合期间抑制查询、结束后恢复查询的分支仍完整；过期结果保护仍保留。

### 9.5 旧文件：按授权删除退役内容

**决定：用户已明确授权删除确认无活动引用的退役内容；删除已完成，低优先级文档同步继续保留。**

`lib/math.ahk`、`lib/jsEval.ahk`、`loadScript/`、`pages/settings.js` 已退出活动运行路径；`tools/ini_parse_check.ahk` 和 `tools/ini_write_check.ahk` 复制旧实现，并包含机器专属路径。用户已明确授权本次删除这些退役文件，因此它们不再属于当前工作树；删除本身不改变运行时行为。

在架构说明中记录已删除文件的原用途、替代入口和删除原因；不重新接入旧 include，不为旧诊断脚本补写新测试。诊断脚本不是当前配置行为的验证依据，不执行它们。

持续核对入口、页面 script 引用及发布清单，确保这些文件不会意外重新参与运行或打包。删除在本次用户授权范围内完成，不通过 `.git/info/exclude` 或 `.gitignore` 隐藏变更。

静态验收：删除状态在代码地图和发布说明中一致；活动入口和发布资源没有误引用；只删除本次授权列出的退役文件，没有重新创建旧文件、目录搬移或新增测试。

## 10. 建议实施顺序与验收方式

1. 集中最小配置元数据和纯值校验；修复多行往返、写入幂等性及日志原文输出。
2. 收回 qbar 路径配置；同步默认文件、示例和说明，固定资源定位。
3. 实现字段差异保存和按变化应用，避免无变化重载和重复翻译请求；随后加入 qbar 配置索引缓存，共用失效规则。
4. 逐项合并 SHA-256、URL 编码和启动热串初始化；单独整理剪贴板恢复边界。清理 qbarDebug 和经引用核实的内部死分支；集中窗口绑定模式元数据。
5. 迁移词典消息队列与 Everything 异步作业，补齐取消、超时和过期结果处理。
6. 最后逐个面板收敛 Host 状态，避免与调度改动同时重写所有生命周期。
7. 整理退役文件说明和架构地图，复核所有 include、页面引用和发布清单；确认授权删除的退役文件不再被引用。

每步使用 `git diff --check`、引用搜索、页面消息与 AHK 字段对照、include/资源路径检查，以及人工控制流审查。保存说明应区分“静态检查完成”和“运行行为已验证”。不运行 AHK（包括 `/validate`）、JavaScript、网络连接检查、Everything、安装器或诊断脚本，不编写测试，不自动提交或发布。

本轮代码整改以工作区变更和计划报告为准；静态检查不等于运行时验证，未运行的行为仍需在允许运行的环境中单独验收。
