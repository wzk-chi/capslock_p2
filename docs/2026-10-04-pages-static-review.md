## 2. 总体结论

项目已有良好的共享基础：页面使用 `theme.css`，复杂弹窗和提示分别复用 `AppDialog` 与 `AppToast`，剪贴板历史已做分页和图片懒加载，Qbar 拼音索引也采用分批处理。审查中没有发现页面直接调用浏览器原生 `alert`、`confirm` 或 `prompt` 的情况。

值得优先处理的集中在三个地方：流式内容逐段全量重绘、笔记列表及预览缓存、Everything 结果选择时的重复排序和重建。其余项目主要是共享逻辑归并、局部重渲染和代码组织，预计收益较温和。

## 3. 优先级较高的性能优化

### 3.1 AI 回答逐段重解析整条 Markdown

`pages/chat.html` 的 `appendStreaming()` 每收到一段文本，就把累计答案重新交给 Marked 和 DOMPurify，再替换整条消息的 `innerHTML`（约第 348、382 行）。长回答、细粒度流式响应下，重复解析和 DOM 写入会随答案增长而增加。

已按 `requestAnimationFrame` 合并聊天页面的 Markdown 重绘；片段仍会即时累积，结束时会取消待处理帧并渲染完整结果。

翻译页面也已将结果片段按帧合并，再一起更新文本、滚动位置和复制按钮状态。

### 3.2 笔记页分页与按需预览（已实施）

`NotesStoreList()` 已按日期、搜索和标签条件查询总数，并以 `LIMIT/OFFSET` 只返回当前页。页大小可选 20、50 或 100；保存或删除后如果原页超出范围，会回退到最后一页。

页面仅在卡片接近视口时生成 Markdown 预览；`notes-preview.js` 在遍历过程中使用 12 行预算，遇到下一项无法容纳时停止继续收集。

`previewHtmlCache` 校验更新时间、Markdown 内容和附件签名，并将缓存限制为最近 64 条，避免同一秒内编辑导致旧预览命中，也避免缓存无限增长。

缓存命中时会更新最近访问次序，超出容量后淘汰最早访问项。

### 3.3 Everything 方向键操作重复排序并重建结果列表

`pages/everything.html` 的 `selectResult()` 会排序结果，随后 `renderResults()` 再次排序并重建全部行；每行会重新创建图标、DOM 和事件处理器（约第 387、443、489 行）。方向键只改变选中项时，整份结果其实没有变化。

已缓存排序结果；方向键和单击选择现在只更新旧、新选中行的 class 与滚动位置，不再排序并重建整份列表。鼠标事件委托仍可作为后续整理项。

### 3.4 剪贴板历史图标刷新（已处理）

复核发现这项已通过 `scheduleIconRefresh()` 按帧合并占位图标刷新，整页渲染后也只刷新一次。本轮无需再改。

## 4. 中优先级整理

### 4.1 设置页只渲染当前激活的分区

`pages/settings.html` 的 `renderAll()` 每次快照都重绘静态控件、自定义热键、快捷键、键位映射和插件视图（约第 1428 行），随后才由 `setPage()` 隐藏未激活页面。很多表单和快捷键节点在当前打开分区时并不可见。

建议按分区惰性渲染：首次打开某个分区时生成 DOM；快照更新只刷新已创建且需要更新的分区。页面切换时保持草稿状态，避免为不可见列表重复创建选项、卡片和事件处理器。

### 4.2 合并跨页面重复的宿主通信与窗口栏逻辑

多个页面仍重复实现 `post()`、`postType()`；此前按历史试验移除的 `cursorMove` 监听现已依当前项目约定收敛到 `panel.js`，八个交互页面共用同一个约 80ms 节流监听。聊天、翻译、词典和 Everything 还各自维护窗口栏标签和 pin 状态文案。

共享通信和窗口栏状态仍有整理空间；`panel.js` 只负责指针恢复事件，不接管页面业务消息。聊天和翻译中的剪贴板复制回退也可考虑抽成共享 helper。共享模块保持职责窄小，不把页面业务状态塞入公共层。

### 4.3 迁移旧主题变量别名

`theme.css` 已提供规范的 `--ui-*` 颜色变量，同时保留 `--bg`、`--ink`、`--accent` 等兼容别名（约第 38–57 行）。`dictionary.html`、`settings.html`、`qbar.html` 仍在使用这些别名。

建议在整理页面样式时迁移到 `--ui-*`；确认没有页面依赖后，再移除旧别名。当前配色仍映射到统一主题，没有发现页面重新引入独立的深浅色切换逻辑。

### 4.4 拆分大页面并恢复多行格式

`settings.html`、`qbar-notes.html` 和 `clipboard-history.html` 都把大量 CSS、HTML 和业务 JavaScript 放在单个文件中；后两者还有若干数百字符的单行函数和事件绑定（例如 `qbar-notes.html` 约第 544、591、646 行，`clipboard-history.html` 约第 148–170、235、316–321 行）。这会增加查找状态来源、审查边界和局部改动的成本。

建议先按职责把长函数改成多行，再将较大的脚本拆到页面专属文件：设置页按配置、快捷键、插件和窗口绑定拆分；笔记页按列表/预览、编辑器、资源上传拆分；剪贴板历史按查询、行渲染、操作协议拆分。继续保持页面入口清楚，避免为了拆分而引入复杂打包层。

### 4.5 笔记页诊断监听（已清理）

复核时该监听器仍会在编辑器打开期间响应每次文档点击并安排 80 毫秒定时器；诊断结论已有记录，本轮已移除这段监听逻辑。
