# 按标签循环复制笔记设计

日期：2026-10-12

状态：已实现。AHK 文件校验、全部警告收集及设置页 JavaScript 语法检查通过；按项目约束未启动应用、运行脚本或编写测试，人工运行验收尚未执行。

## 1. 目标与使用方式

快捷键为 **CapsLock + 反引号键**，即 Esc 下方通常标有反引号和波浪号的键，AHK 扫描码为 `SC029`，对应现有 CapsLock 层的 `caps_backquote`。

第一版固定使用“提示词”标签。按一次组合键，将一篇笔记的完整正文复制到系统剪贴板；再次按下，复制下一篇；最后一篇之后回到第一篇。鼠标旁短暂显示当前笔记标题。

假设符合条件的笔记按创建顺序为 A、B、C、D、E：

| 按下次数 | 剪贴板正文 | 鼠标旁提示 |
| --- | --- | --- |
| 1 | A 的正文 | 已复制：A |
| 2 | B 的正文 | 已复制：B |
| 5 | E 的正文 | 已复制：E |
| 6 | A 的正文 | 已复制：A |

每次操作只复制一篇，由用户自行粘贴；不打开笔记窗口、不切换前台应用，也不发送粘贴按键。提示只显示标题，不计算循环序号和总数。

## 2. 内容、顺序与进度

- 按完整标签名“提示词”匹配，沿用 `tags.name` 的 `COLLATE NOCASE` 语义；“提示词模板”等名称不匹配。
- 一篇笔记有多个标签时，只要包含“提示词”就参与循环，同一篇只出现一次。
- 只读取已保存的完整正文。正文超过 4000 字符时也必须完整复制，不能使用列表预览。
- 不额外拼接笔记标题、标签或分隔线。正文中用户写入的标题属于正文，原样保留。
- 保留 Markdown 源文本、代码块和换行；内部图片引用复用 `NotesExternalizeMarkdown()`，将 `![说明](asset:...)` 转为 `[说明]`，无说明时沿用现有的 `[]` 输出。第一版不复制图片二进制或渲染富文本。
- 空正文，或仅含空格、制表符、回车和换行的正文，跳过。

按现有自增主键 `notes.id ASC` 循环，即稳定的创建顺序。置顶、改标题和改正文不改变循环位置。页面按最近更新排列，用于浏览；循环采用创建顺序，避免一次编辑就打乱遍历。

唯一的进度是“上次成功复制的笔记 ID”，初始为 0。下一次选择 ID 大于该值的第一篇符合条件的笔记；没有则回到 ID 最小的一篇。标题和正文相同的不同笔记仍分别参与循环。

| 情况 | 下一次按下时的行为 |
| --- | --- |
| 修改标题或正文并保存 | 复制新内容，创建顺序不变 |
| 新增带目标标签的笔记 | 加入循环末尾；刚复制过原末篇时，先复制新增篇再回绕 |
| 已有笔记加入标签 | 按原 ID 加入；ID 小于游标时，在下次回绕后复制 |
| 笔记移出标签、被删除或正文变空 | 自动跳过 |
| 上次复制的笔记已不在候选中 | 仍以其 ID 前进，没有更大的候选则回绕 |
| 标签不存在、改名或全部正文为空 | 不写剪贴板，提示空结果，并将游标重置为 0 |
| 只有一篇符合条件 | 每次复制该篇 |

进度只在内存中保存。松开 CapsLock、切换应用、普通复制、等待或关闭笔记页面均不重置；程序重启后从第一篇开始。每次触发读取当前数据，不保存整轮内容快照，不维护笔记变更通知或候选缓存。

“提示词”是用户指定的第一版固定业务范围，不新增标签设置。快捷键默认值继续通过现有数据库默认配置机制发布。

## 3. 快捷键与提示

### 3.1 按一次执行一次

默认组合键和重新映射后的动作均执行一次物理按下、一次复制。可以一直按住 CapsLock，反复按下、松开反引号键来循环；持续按住触发键不因系统重复事件跳过多篇。

防重复由输入层提供一个共享的单次触发包装，CapsLock 层和自定义快捷键入口复用：

- CapsLock 层注册回调时传入实际 `physicalKey`，沿用现有 `LayerKeyNames`；不在动作函数里固定等待 `SC029`。
- 自定义快捷键使用已通过校验的规范化 trigger，沿用现有校验中剥离 `^!+#` 前缀的规则取得触发键。修饰键不作为等待对象。
- 仅当最终解析的内置动作是 `keyFunc_notesCyclePrompt` 时应用单次触发策略；其他动作保持现有输入语义。
- 执行完成后在 `finally` 中对实际键调用 `KeyWait(triggerKey)`，覆盖成功、空结果和失败路径；现有同一热键单线程限制抑制松开前的系统重复。
- 鼠标按键等具有按下/松开状态的受支持输入同样等待释放；滚轮是离散事件，每个事件执行一次，不调用 `KeyWait`。
- 等待期间其他快捷键仍按现有 AHK 调度方式工作；不增加 Sleep、轮询或独立按键监听。

沿用现有 `$` 钩子前缀、快捷键录制保护和全局/应用专属映射优先级。动作识别使用白名单中的稳定标识，不依赖显示名称。

### 3.2 鼠标旁提示

复用 `ShowMsg()` 和原生 `ToolTip`。成功显示 `已复制：标题`，约 1400 毫秒；标题为空时显示“无标题”，显示前合并标题中的换行和制表符。

连续触发替换同一个提示，并从最后一次提示重新计时。提示位于每次触发时的鼠标附近，不获取焦点；清除复用已有回调，不持续追随鼠标或新增窗口。

空结果提示：`“提示词”标签下没有可复制的正文，请给笔记添加该标签并保存内容。`

读取失败和写入失败分别提示 `暂时无法读取笔记，请稍后重试。`、`复制失败，请稍后重试。`，约 2500 毫秒。SQL、路径、内部 ID 和异常详情仅写日志。

## 4. 最小接入方式

执行路径为：

`现有快捷键分发 → keyFunc_notesCyclePrompt → NotesCycleCopyNextPrompt → 笔记存储 → NotesSetClipboard → ShowMsg`

`keyFunc_notesCyclePrompt` 是无参数内置动作，映射目标为 `@builtin:shortcut/keyFunc_notesCyclePrompt`。只加入现有动作白名单和设置显示名称，入口直接调用集中实现的笔记循环服务，快捷键分支不承担标签查询或循环业务。

第一版不新增 Qbar 命令、别名、候选项、专用历史类型或使用统计，也不调整注册表的展示名称规则。这个动作的可用性由现有快捷键映射控制，不额外依赖 Qbar 插件启用状态。

复用现有笔记存储、Markdown 导出、剪贴板写入和提示能力；如果以后增加 Qbar 入口，按项目规范注册命令，并调用同一个循环服务。

正文直接使用 `NotesExternalizeMarkdown(note["content"])`，无需再包一层只转发的帮助函数。`NotesCopyTextForExternal()` 会额外拼接标题，保留其现有用途，本功能不调用它。

## 5. 下一篇查询与循环服务

### 5.1 索引查询

在 `qbar_notes_store.ahk` 新增 `NotesStoreReadNextTaggedNote(tagName, afterId)`。结果区分：

- `ok`：返回 `id`、`title`、完整 `content`。
- `empty`：查询成功但没有符合条件的笔记。
- `error`：初始化或查询失败，诊断沿用 `NotesStoreError`。

先查询 ID 大于游标的第一篇；结果为空且游标大于 0 时，以 0 再查一次完成回绕。首次使用或命中下一篇时只查一次，回绕时最多两次；任一次查询失败都返回 `error`，不能误当成空结果。

查询形状如下。`${tagSql}` 代表经 `NotesStoreSql()` 转义的标签值，`${afterId}` 代表经过校验的非负整数：

```sql
SELECT n.id, n.title, n.content_md
FROM tags t
JOIN note_tags nt ON nt.tag_id = t.id
JOIN notes n ON n.id = nt.note_id
WHERE t.name = ${tagSql}
  AND nt.note_id > ${afterId}
  AND trim(n.content_md, char(32, 9, 10, 13)) <> ''
ORDER BY nt.note_id ASC
LIMIT 1;
```

查询从完整标签名进入，利用现有标签唯一索引及 `idx_note_tags_tag(tag_id, note_id)` 做关系筛选和 ID 范围查找。跳过空正文后即可返回一篇，不计算全体候选的排名和数量，不使用窗口函数、全量内容缓存或新索引。

每条 SELECT 读取其执行时的数据；回绕不要求与前一次空查询共用事务快照，按第二次查询时的有效候选返回即可。返回后复制该次读取的完整正文，不额外重查。只有笔记存储模块访问笔记表，业务查询不修改笔记、标签或时间戳。

### 5.2 成功后推进

在 `lib/features/qbar/qbar_notes_cycle.ahk` 集中实现循环服务，仅有两个可变状态：

| 状态 | 含义 |
| --- | --- |
| lastCopiedNoteId | 上次成功写入系统剪贴板的笔记 ID，初始 0 |
| running | 防止服务嵌套执行，在 finally 中恢复 |

处理顺序：

1. 输入入口完成现有映射和白名单校验；服务进入重入保护。
2. 调用存储接口读取下一篇。空结果重置游标并提示；读取错误保留游标并提示；两者均不写剪贴板。
3. 调用现有 Markdown 导出函数，防御性检查文本非空。
4. 调用 `NotesSetClipboard(text, "user-copy")`。
5. 写入成功后提交笔记 ID，再显示标题；写入失败不推进游标。

不创建待复制队列或延迟复制任务。关闭笔记窗口及页面闲置销毁不重置状态；应用结束时内存状态自然释放。

日志记录结果、笔记 ID、失败阶段和异常类型，不记录正文、剪贴板文本或完整标题。

## 6. 剪贴板一致性

### 6.1 复用共享写入

复用 `NotesSetClipboard()` 的暂停令牌、所有权序列、系统槽位标记和显式剪贴板历史发布。复制按现有普通用户复制规则记录剪贴板历史；历史关闭仍能复制。这与新增 Qbar 动作历史是两种不同用途。

成功以实际写入系统剪贴板为准。镜像同步、历史发布或提示失败不撤销已经成功的复制，也不回退游标；共享写入帮助函数应隔离这些附属步骤的异常。

### 6.2 先失效旧镜像，再同步新镜像

当前 `HandleClipboardChange()` 在 CapsLock 按住或监听暂停时不会更新 `SystemClipboard`。因此共享写入帮助函数需统一完成以下步骤：

1. 成功写入后记录本次剪贴板序列，设置 `WhichClipboardNow := 0`，立即使被覆盖的旧系统镜像失效，即 `SystemClipboard := 0`。
2. 调用 `SaveClipboardSlot(0, expectedSequence)` 捕获新镜像。只有返回有效快照且序列匹配时，才把它作为当前系统镜像。
3. 捕获异常或序列不匹配时记录日志，不重新使用旧镜像、不回写剪贴板，也不在失败处理末尾再次清空可能已由更晚写入更新的镜像。
4. 成功快照可直接供现有显式历史发布使用，避免同一次复制重复抓取 `ClipboardAll`。

旧镜像失效与槽位标记由共享写入接口集中处理，不放进循环服务。涉及内存状态的提交保持短小；不把数据库等待、快照读取或提示显示放进长临界区。

### 6.3 首次槽位操作前按需初始化

程序启动时 `SystemClipboard` 为 0，注册剪贴板监听不会捕获初始内容。首次独立槽位操作前，如果当前是系统槽且镜像不存在，必须先保存当前系统剪贴板，再执行可能覆盖它的操作。

共享入口 `PrepareClipboardSlotChange()` 由独立槽位复制、剪切、粘贴及现有 `clipSaver` 的独立槽位分支复用：

- 仅当 `WhichClipboardNow = 0` 且镜像不存在时，调用 `SaveClipboardSlot(0, expectedSequence)` 补捕；镜像已有效时不重复捕获，不增加启动阶段的读取。
- 捕获成功后继续原有槽位操作，Ctrl+V 可以恢复槽位操作前的系统内容。
- 捕获异常或序列不匹配时，停止该次槽位操作，提示“当前剪贴板暂时无法保留，请稍后重试。”并记录诊断；不发送复制、剪切或粘贴，不改变当前槽位。
- 已处于其他槽位时不从其内容反推系统镜像，保留镜像失效时的防错恢复规则。

笔记复制后的镜像捕获失败，也可在下一次切入独立槽位前补捕当前系统内容；补捕仍失败时保留当前剪贴板，用户仍能直接粘贴。

### 6.4 镜像不可用时的粘贴行为

`PasteSystemClipboard()` 区分当前槽位：

| 状态 | 行为 |
| --- | --- |
| `WhichClipboardNow = 0` | 当前系统剪贴板可直接粘贴，即使镜像捕获失败 |
| 已切换到其他槽位，且系统镜像有效 | 沿用现有恢复系统镜像后粘贴的流程 |
| 已切换到其他槽位，且系统镜像失效 | 不恢复旧内容、不发送粘贴，提示“上次复制的内容未能保留，请重新复制。” |

后续成功的系统复制会重新建立镜像。这样镜像失败不会妨碍本次直接粘贴，也不会在槽位切换后把旧内容或其他槽位内容误当作本次正文。

读取失败和空结果保证本功能未修改剪贴板；写入过程异常不承诺旧剪贴板一定保留，不做盲目恢复。

人工运行验收条件如下；本次仅完成源码实现与静态检查，未启动应用执行这些验收：

1. 五篇笔记连续按六次，依次复制第 1、2、3、4、5、1 篇的完整正文，提示标题一致。
2. 默认反引号、重新映射的键盘键及鼠标按键按住时均只执行一次；松开后再次按下可继续；滚轮每个离散事件执行一次。
3. 超过 4000 字符的正文完整复制，标题不额外拼入，Markdown 和内部图片导出符合约定。
4. 提示在鼠标附近出现，不改变前台焦点、不自动粘贴，连续触发刷新显示时间。
5. 编辑、置顶、增删笔记、标签变更和空正文按第 2 节处理；重名标题不影响游标。
6. 切换应用、普通复制、等待和关闭页面保留进度，重启从第一篇开始。
7. 空结果不清空剪贴板；数据库或写入失败不推进游标；附属步骤失败不撤销复制。
8. 镜像同步成功时，经过其他槽位操作仍可恢复本次正文；镜像失败时本次直接粘贴可用，切入独立槽位前的补捕失败则停止该次操作，已处于其他槽位时仍阻止错误恢复。
9. 剪贴板历史关闭仍能复制；已有快捷键覆盖、应用专属映射和录制保护继续生效。
10. 启动前系统剪贴板已有内容，启动后尚未进行普通复制就首次复制/剪切到独立槽位 1 或 2，Ctrl+V 恢复初始系统内容；独立槽位仍可粘贴其新内容。初始系统剪贴板为空时也能建立有效空镜像，不误报保存失败。
